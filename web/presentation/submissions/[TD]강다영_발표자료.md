## 2. 대표 작업 선택

### 대표 작업

**작업명**: 프로젝트의 기술 디렉터로서의 개발 총괄, 시스템 설계 및 개발 구조 구축

**이 작업을 대표 사례로 선택한 이유**: 프로젝트의 개발에 있어 기반을 다지는 작업과 해당 기반을 바탕으로 기능을 잘 쌓아올리는 것이 중요하다고 생각합니다. 그 과정에 있어 기초 공사 작업을 수행하는 프로토타입의 단계와, 개발 과정을 감독한 작업은 TD의 역할을 잘 나타내는 작업일 것입니다.

**이 작업에서 본인이 맡은 정확한 범위**:
 - **프로젝트의 폴더 구조 설계 및 관리**: 개발 초기 단계에서 폴더 구조를 설계하고, 각 파일의 책임을 명확히 정의하여 코드의 유지보수성을 극대화
 - **데이터 관리 시스템의 구축**: 게임의 다양한 데이터를 효율적으로 관리하기 위해 데이터의 속성을 고려한 데이터 관리 시스템 구축 
 (JSON, ScriptableObject 등 사용)

### 보조 작업 — 선택

**작업명**: UI 시스템의 모듈화 설계

**선택 이유**: P0에서 진행했던 '기반을 다지는 작업' 중 하나로서, 대표 작업에 대한 예시로 보여주기 좋음. UI 하나를 하나의 모듈로 취급하여, 독립적으로 관리 및 확장이 가능하도록 `UIManager` 기반의 통합 아키텍처 리팩토링을 수행했음을 보여줄 수 있기 때문.

## 3. 대표 작업 설명

### 3.1 완성 결과

**작성**: 프로젝트의 시작 단계에서, '계층형 아키텍쳐'를 기반으로 한 프로젝트의 개발의 기반을 다지는 작업을 진행했습니다. 기능에 따라 파일을 분리하고, 각 파일의 책임을 명확히 정의하여 유지보수가 용이한 코드를 작성했습니다. 이때, Assambly Definition을 이용하여 규칙을 더욱 견고히 하였습니다.
이를 통해 스크립트간의 무분별한 호출을 방지하고, 의존성을 낮추어 스크립트간의 순환 참조로 인한 문제가 발생하지 않을 수 있었습니다. 또한 기능별로 스크립트를 분류했기 때문에 코드를 전달받은 다른 팀원들이 혼동하지 않고 기능을 쉽게 파악하여 추가 개발을 진행할 수 있는 환경을 도모했습니다.

### 3.2 작업 목표

**작성**: 기능에 따라 파일을 분리함으로써 개발 과정에서의 버그를 최소화 하고, 만일 디버깅 사항이 발생 하더라도 빠르게 대처할 수 있는 환경을 구축하고자 하였습니다.

### 3.3 핵심 문제 또는 제약

**작성**: 기능이 추가됨에 따라 스크립트 간의 의존성이 높아지면, 이는 코드의 유지보수성을 저하시키는 결과를 가져올 수 있습니다. 또한 이러한 구조는 순환 참조로 인한 문제를 야기할 수 있습니다.

### 3.4 사용 기술과 선택 이유

**사용 기술**:
- `Assembly Definition (asmdef)` : 기능별로 물리적인 코드 종속성을 강제하고 불필요한 참조 방지를 통해 컴파일 시간을 단축
- `단일 책임 원칙(SRP) 기반 모듈화 설계` : 기능별로 파일을 분리하여 코드가 비대해지고, 기능 추가 시 예기치 못한 사이드 이펙트가 발생하는 문제를 해결
- `계층형 아키텍쳐` : 게임의 핵심 로직을 계층화하여 구조적인 안정성을 확보

**선택 이유**: 규칙이 존재하지 않은 상태로 개발할 경우 각 기능별 파일 간의 참조가 자유로웠으나, 이는 점차 코드의 비대화와 순환 참조 문제를 야기한다는 것을 이전 프로젝트에서 경험 했습니다. 이번 프로젝트에서는 이러한 문제점을 해결하기 위해 게임의 핵심 기능들을 물리적인 단위로 분리하는 모듈화 설계를 적용했습니다. 또한 Assembly Definition을 도입하여 각 기능별 코드의 의존성을 명시적으로 관리함으로써, 불필요한 컴파일 시간을 단축하고 코드의 안정성을 확보할 수 있었습니다.

### 3.5 구현 결과

**작성**: 걔층형 아키텍쳐의 구조 위에 모듈화 설계를 적용하여 게임의 핵심 기능들을 물리적인 단위로 분리할 수 있었습니다. 또한 Assembly Definition을 도입하여 각 기능별 코드의 의존성을 명시적으로 관리함으로써, 불필요한 컴파일 시간을 단축하고 코드의 안정성을 확보할 수 있었습니다.

### 3.6 남은 한계 또는 개선점

**작성**: 규칙이 존재하는 개발 환경 속에서 프로젝트를 진행하는 것에 대한 장점을 가져갈 수 있었지만, 해당 구조에 대한 설계자 본인의 이해도 부족과 팀원들에게 구조에 대한 명확한 안내가 이루어지지 않았기 때문에 초기 개발 과정에서 혼란이 발생하기도 하였습니다.
