## 1. 발표용 핵심 요약

### 대표 작업 — 꿈식자 컨셉 기획 및 AI 설계·구현·안정화

송예찬은 6월 14일 구버전 몬스터 컨셉 기획서에서 기본 꿈식자를 다음과 같이 정의했습니다.

> “침몽도시 골목길을 2~3마리씩 배회하는 하위 침식체”

이후 P0.5 기획에서는 기본 위협체의 핵심을 다음처럼 확장했습니다.

> “소리, 탐색, 추격 기억, 먹잇감 차단 이동, 루시드 낙인을 통해 긴장감을 형성”

이 설계의 출발점은 꿈식자를 단순한 전투용 몬스터로 보지 않고, 악몽 속을 돌아다니며 사람들의 꿈과 기억을 먹는 세계관 속 포식자로 표현하는 것이었습니다. 가장 기본적인 적이므로 강력한 단일 개체보다는 2~3마리가 무리를 이루어 배회하도록 설정했습니다. 각 개체가 고도의 협동 전술을 수행한다고 과장하지 않고, 동일한 시야·소리 자극에 반응하면서도 각자의 순찰 루트와 접근 위치를 유지하게 하여 무리가 먹잇감의 이동 경로를 압박하는 인상을 만들었습니다.

기획자·개발자 역할로 이 컨셉을 개발 연동 명세로 구체화하고 Unity에서 시야·소음 조사, 추격 기억, 랜덤 순찰·복귀, 먹잇감 차단, 어그로 관리, 낙인·의식 누출, 디코이 타겟 분리와 전투 피드백까지 구현했습니다. 이 AI 업무는 PM 권한으로 수행한 것이 아니라 별도로 맡은 기획·개발 업무입니다. PM 역할에서는 공식 계획의 P0 안정화 게이트, 주간 일정, 우선순위와 이월을 관리했습니다.

### 보조 작업 — 기획안 기반 튜토리얼 런타임 진행 시스템

튜토리얼 원안은 문서 메타데이터상 우성혁 CD·장수영 CP가 기획했습니다. 송예찬은 이 기획을 기반으로 독립 씬, JSON 단계 데이터, 대화·무전·조작 UI, 입력 차단, 전투 구간 차단, 사망 방지, 상자·적 처치·탈출 이벤트를 실제 런타임에 구현했습니다.

## 3. 컨셉에서 구현까지

### 3.1 구버전 기본 꿈식자

- 목적: 기본 꿈식자의 비주얼·행동과 P0 범위 정의
- P0 대상: `Monster_Test` 1종
- 기본 행동: 감지·추적, 근접 공격, 사망 시 아이템 생성
- 작성 이력: 2026-06-14 v0.1, 06-15 v0.2, 06-16 수정안 — 송예찬

### 3.2 P0.5 행동 확장

- 직접 시야는 짧고 제한된 각도와 Raycast를 사용
- 소리는 플레이어 좌표가 아닌 발생 위치만 제공
- 시야를 잃어도 추격 기억과 마지막 위치 탐색 유지
- 플레이어의 짧은 미래 위치를 계산하는 먹잇감 차단 이동
- 피격 시 시간 자원과 은신 안정성을 잠식하는 루시드 낙인·의식 누출
- 추격 해제 후 자기 순찰 루트로 복귀

#### 순찰의 통제된 무작위성

- 존 안의 후보 스폰 포인트 중 필요한 수만큼 무작위 선택
- 스폰 지점별 패트롤 루트와 가장 가까운 시작 포인트 연결
- 각 패트롤 포인트 주변에서 `Random.insideUnitCircle`로 후보 좌표 생성
- `NavMesh.SamplePosition`과 완전 경로 검증을 통과한 지점만 실제 목적지로 사용
- 배회 횟수·대기 시간·다음 인접 포인트를 무작위로 선택해 같은 루트의 반복감 완화

#### 소리 인식에서 어그로 종료까지

```text
소리 반경·차단 여부 확인
→ 소리 종류별 우선순위 등록
→ 발생 위치를 NavMesh 위 조사 지점으로 보정
→ 조사 지점 이동·주변 탐색
→ 플레이어 시야 인지
→ 추격·공격 + 어그로 생성
→ 시야 유지: 어그로 회복
→ 시야 상실: 유예 후 어그로 감소
→ 어그로 소진 또는 활동 반경 이탈: 자기 패트롤 루트 복귀
```

어그로는 단순 ON/OFF가 아니라 추격을 얼마나 유지할지 결정하는 시간 기반 값입니다. 플레이어를 계속 확인하면 회복되고, 시야를 잃으면 유예 시간 후 감소합니다. 루트에서 멀어지면 더 빠르게 감소하며, 하드 리턴 거리를 넘으면 시야와 관계없이 즉시 복귀합니다.

## 4. 일정 관리가 결과에 미친 영향

송예찬은 PM 역할로 일정표의 요일·실적을 갱신하고 주간 개발일지를 취합하며 우선순위와 이월을 관리했습니다. 이는 꿈식자 AI를 기획·개발한 역할과 별개입니다. 발표에서는 두 책임을 섞지 않고, PM 성과는 프로젝트 운영으로, AI 성과는 기획자·개발자로서의 작업으로 설명합니다.

```text
P0 최소 감지·추적
→ P0.5 소음 조사·차단 이동
→ 복귀·타겟·충돌 안정화
→ 피격 피드백·처치 보상
```

공식 일정표는 7월 11일 P0 안정화를 P0.5 착수 조건으로 두었지만, 실제로는 6월 26일부터 시야·AI 기능을 선행 검증했습니다. 따라서 발표에서는 계획을 그대로 준수했다고 설명하지 않고, 안정화 게이트를 관리하면서 선행 가능한 AI 기능을 병행하고 피드백에 따라 범위를 조정한 과정으로 설명합니다.
