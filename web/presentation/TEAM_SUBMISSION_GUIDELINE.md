# 📢 《침몽도시: 루시드 다이버》 최종 발표 설계 가이드라인

> 본 문서는 팀원들이 최종 발표 웹페이지에 반영할 발표 내용을 직접 설계하고 작성할 수 있도록 안내하는 가이드라인입니다.

---

## 1. 문서 목적

- 본 문서는 프로젝트 전체 작업 이력을 단순 나열하는 문서가 아닙니다.
- **최종 발표에서 본인이 실제로 청중과 코치에게 말하고 보여줄 핵심 발표 내용**을 직접 결정하는 발표 설계 가이드입니다.
- 발표 내용은 작업 전체를 나열하지 말고, **대표 작업 1개(필요시 보조 작업 1개)**만 선택하여 작성합니다.
- 팀원이 발표 웹 코드를 직접 수정하지 않아도 됩니다. 제출 문서(`submissions/`)에 아래 형식대로 작성하면 발표 웹페이지에 그대로 반영됩니다.

---

## 2. 발표 자료 작성 절차

1. **본인 요약 문서 확인**:
   - `team_summaries/[본인 작업물 요약 문서]`를 열어 본인의 전체 작업 이력과 구현 결과를 확인합니다.
2. **대표 작업 선택**:
   - 본인이 발표할 대표 작업 1개를 선택합니다. (필요하다면 보조 작업 1개 추가)
3. **발표 핵심 메시지 작성**:
   - 발표가 끝난 후 청중이 기억해야 할 한 문장을 작성합니다.
4. **장면 순서 설계**:
   - Scene 1부터 Scene 5까지 화면에 보여줄 요소와 말할 내용을 순서대로 정합니다.
5. **필요 에셋 준비**:
   - 발표 화면에 보여줄 영상(.mp4), 이미지(.png), GIF, 코드 스니펫 등을 준비합니다.
6. **원하는 웹 연출 선택**:
   - 웹페이지에서 구현되길 원하는 시각 연출 효과를 체크합니다.
7. **발표 대본 작성**:
   - 실제로 시연하며 말할 대본 초안을 작성합니다.
8. **최종 확인**:
   - 다른 팀원과의 내용 중복 여부 및 제한 시간 내 발표 가능 여부를 점검합니다.

---

## 3. 대표 작업 선택 기준

- **실제 기여도**: 실제로 본인이 직접 설계하고 구현하거나 결정한 작업인가?
- **시각적 시연성**: 화면이나 영상, 동작 GIF, 오디오 등으로 명확하게 보여줄 수 있는가?
- **핵심 경험 연결**: 프로젝트의 핵심 플레이 루프나 플레이어 경험과 긴밀하게 연결되는가?
- **설명 용이성**: 제한된 발표 시간 내에 기술적 판단 이유를 명확히 설명할 수 있는가?
- **팀원 간 차별성**: 다른 팀원의 발표 주제와 중복되지 않는가?

## 4. 대표 작업 작성 예시

### ❌ 나쁜 작성 예시 (단순 기술명 및 작업목록 나열)
- AudioManager 구현
- FSM 구현
- ResultUI 구현
- SettingUI 구현
- 대사 필터 구현

---

### ⭕ 좋은 작성 예시 (목표 - 판단 - 연출 중심)

**대표 작업**:
3D 공간 오디오 시스템

**완성 결과**:
적과 환경음의 위치에 따라 거리감이 달라지는 공간 음향을 구현했다.

**작업 목표**:
어두운 공간에서 화면 밖 위험을 소리로 인지하게 만들고자 했다.

**기술적 선택**:
AudioSource 3D 감쇄와 중앙 AudioManager 구조를 사용했다.

**발표 시연**:
같은 발소리를 가까운 거리와 먼 거리에서 번갈아 재생한다.

## 5. 웹 연출 선택 가이드

발표 웹페이지 구축 시 사용할 수 있는 시각적 연출 옵션입니다. `submissions/` 문서 작성 시 필요한 연출을 체크해 주세요.

- **결과 영상 자동 재생**: 페이지 진입 시 실기 시연 영상 자동 재생
- **Before / After 비교**: 기존 문제 상태와 해결 후 상태를 슬라이더/토글로 비교
- **이미지 특정 영역 확대**: 맵 조감도나 UI의 특정 부분을 줌인 강조
- **코드와 실행 결과 동시 표시**: 좌측 C# 코드 스니펫과 우측 실행 동작 GIF 나란히 배치
- **FSM / 단계별 강조**: Idle ➡️ Chase ➡️ Attack 상태 변화 시 다이어그램 노드 하이라이트
- **맵 경로 애니메이션**: 레벨 맵 상에서 플레이어 동선이 선으로 그려지는 연출
- **오디오 비교 재생**: 온/오프 상태의 오디오 샘플을 직접 들어보는 오디오 플레이어
- **UI 화면 단계별 전환**: 클릭에 따라 UI 레이어가 하나씩 레이어드되어 열리는 연출
- **구현 전후 토글**: 버튼 하나로 셰이더 적용 전/후 화면 전환

## 6. 제출 에셋 규격 및 폴더 구조

각 팀원은 본인의 전용 에셋 폴더 아래에 영상, 이미지, 오디오 파일 등을 배치하고, `submissions/` 문서에 파일명을 명확히 적어주세요.

```text
web/presentation/
├─ assets/
│  ├─ [CP]장수영/
│  │  ├─ videos/
│  │  ├─ images/
│  │  └─ audio/
│  ├─ [CD]우성혁/
│  │  ├─ videos/
│  │  ├─ images/
│  │  └─ audio/
│  ├─ [PM]송예찬/
│  │  ├─ videos/
│  │  ├─ images/
│  │  └─ audio/
│  ├─ [PD]김남해/
│  │  ├─ videos/
│  │  ├─ images/
│  │  └─ audio/
│  └─ [TD]강다영/
│     ├─ videos/
│     ├─ images/
│     └─ audio/
│
├─ team_summaries/          (참고자료: 개인 전체 작업물 요약)
│  ├─ [CP]장수영_작업물_요약.md
│  ├─ [CD]우성혁_작업물_요약.md
│  ├─ [PM]송예찬_작업물_요약.md
│  ├─ [PD]김남해_작업물_요약.md
│  └─ [TD]강다영_작업물_요약.md
│
└─ submissions/             (팀원 직접 작성 발표 설계 문서)
   ├─ [CP]장수영_발표자료.md
   ├─ [CD]우성혁_발표자료.md
   ├─ [PM]송예찬_발표자료.md
   ├─ [PD]김남해_발표자료.md
   └─ [TD]강다영_발표자료.md
```

### 파일 배치 예시 (`assets/[CD]우성혁/` 기준)
- `videos/representative.mp4` (대표 시연 영상)
- `images/before.png` (문제 상황 스크린샷)
- `images/after.png` (개선 후 스크린샷)
- `images/diagram.png` (구조도 또는 FSM 다이어그램)
- `images/code.png` (주요 코드 스니펫)

---

## 7. 발표 설계 문서(`submissions/`) 작성 템플릿 사용법

1. `web/presentation/submissions/[본인이름]_발표자료.md` 파일을 연다.
2. `team_summaries/` 문서를 옆에 띄워두고 참고한다.
3. 문서 안의 안내문과 빈칸을 확인하여 본인이 발표할 내용을 직접 채워 넣는다.
4. 직군별 하단 보조 질문을 답변하며 내용을 구체화한다.
