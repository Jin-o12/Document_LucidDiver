## ✅ 완료한 작업

### 1. 튜토리얼 UI 구조 확장 및 흐름 분리
- **내용**: 
  - 새 튜토리얼 기획서 기준으로 기존 6단계 구조를 유지하면서 UI 표현 방식을 다각화함.
  - 단순 안내 팝업, 관제사 무전, 유안 대사, 조작 툴팁을 각각 명확히 구분하여 개별 UI 흐름으로 분리함.
  - 무전/대화 계열은 유저 편의를 위해 별도의 Next 버튼 클릭 없이 패널 자체를 클릭해도 다음 대사로 넘어갈 수 있도록 입력 방식을 개선함.
  - 유안 대사창에는 대화 몰입도를 위해 캐릭터 스탠딩 이미지를 배치할 수 있도록 UI 구조를 세분화함.
  - 관제사 무전은 유안 대사창과 차별화되도록 화면 중앙 무전 안내에 가깝게 별도 UI로 독립시킴.
- **결과**: 기획서 요구사항에 맞는 다채롭고 직관적인 튜토리얼 대화/안내 연출 인터페이스 구축.

### 2. 튜토리얼 데이터 갱신 및 테이블 연동
- **내용**: 
  - `TutorialGuide.xlsx`를 최신 기획 사양에 맞춰 추가 및 갱신하고, 이를 파싱하여 `TutorialGuide.json`을 업데이트하는 데이터 파이프라인을 확립함.
  - 튜토리얼 안내 데이터 포맷을 보강하여 무전 대사와 조작 가이드 속성을 유연하게 결합함.
  - 대사 문구, 출력 순서, 트리거 조건, 다음 가이드 연결 ID 등을 데이터 테이블에서 즉각 제어할 수 있도록 구조화함.
  - 튜토리얼 문구가 깨져 보이는 레이아웃 이슈를 해결하기 위해 TMP(TextMesh Pro) 폰트 설정 및 UI 텍스트 컴포넌트 참조 관계를 전면 재점검함.
- **결과**: 데이터 기반의 튜토리얼 기획 관리가 용이해졌으며 텍스트 출력의 가독성 향상.

### 3. 튜토리얼 입력 차단 보강 (인게임 전파 완화)
- **내용**: 
  - 튜토리얼 안내창의 버튼 클릭 또는 화면 터치 입력이 인게임 조작(이동, 발사, 공격 등)으로 동시 전달되는 입력을 방지함.
  - 안내창이 활성화되어 유저의 확인을 기다리는 동안에는 플레이어의 입력 처리가 무시되도록 차단 장치를 보강함.
  - 동일 프레임에서 UI 클릭 이벤트와 플레이어 액션 바인딩이 겹치는 현상을 개선함.
- **결과**: 튜토리얼 팝업을 클릭할 때 캐릭터가 오동작하거나 원치 않는 공격을 가하는 오조작 현상 완화.

### 4. 창고 → 인게임 퀵슬롯 UI 동기화 수정
- **내용**: 
  - 창고(인벤토리)에서 퀵슬롯에 아이템을 배치한 후 인게임 세션에 진입했을 때 UI상에 즉시 표기되지 않던 이슈를 추적함.
  - 퀵슬롯 데이터 복원 이벤트가 UI 인스턴스인 `GamePlayUI`가 완성되기 전에 먼저 호출되어 이벤트를 유실하고 있었던 타이밍 문제로 확인됨.
  - 이를 보완하기 위해 `QuickSlotGroupUI.SyncFromInventory()` 메서드를 새롭게 구현하여, UI 초기화 시점에 `PlayerInventory.quickSlots` 데이터를 강제로 1회 다이렉트 동기화하도록 처리함.
- **결과**: 씬 전환 직후 데이터 누락 현상 없이 장착 중인 퀵슬롯 아이템이 정확하게 표기됨.

### 5. 창고 슬롯 UI 레어리티 프레임 표시 보강
- **내용**: 
  - 창고 인벤토리 슬롯, 퀵슬롯, 아티팩트 슬롯 간의 아이템 레어리티(Rarity) 연출이 상이하게 나타나던 시각적 오류를 일원화함.
  - 아이템 고유 ID(TID)를 기준으로 레어리티 정보를 일괄 조회하고, 등급에 상응하는 레어리티 프레임을 업데이트하도록 처리함.
  - 퀵슬롯 내 아이템 아이콘이 슬롯 경계 밖으로 넘치거나 왜곡되지 않도록 최대 스케일 제한 규칙을 추가함.
  - 비어 있는 퀵슬롯이 활성화된 것처럼 밝게 표시되어 인벤토리 빈 슬롯과 괴리감을 주던 톤을 인벤토리 톤에 맞춰 조율함.
  - 아티팩트 장착 슬롯에 `Image-RarityFrame` 오브젝트가 존재하지 않을 경우를 대비하여 런타임에 동적으로 생성 및 보완되도록 설계함.
- **결과**: 창고 내 모든 슬롯의 시각적 일관성을 확보하고 기획 표준 디자인 규칙을 충족함.

### 6. 창고 드래그 앤 드롭 슬롯 교환 규칙 정리
- **내용**: 
  - 퀵슬롯의 오등록 방지를 위해 소비 아이템(Consumables)만 등록 가능하도록 필터 및 검사 로직을 추가함.
  - 퀵슬롯 간의 드래그 앤 드롭을 통한 상호 위치 교환(Swap)이 자연스럽게 이루어지도록 흐름을 정비함.
  - 아티팩트 슬롯 역시 아티팩트 슬롯 상호 간에만 교환되도록 제한 규칙을 둠.
  - 아티팩트 장착 및 해제는 명확한 슬롯 드롭 및 인벤토리 인터랙션 방식으로 한정하고, 패널 빈 공간에 무분별하게 드롭하여 의도치 않게 해제되는 예외 상황을 방지함.
  - `StorageInventoryUI`가 이러한 인벤토리-슬롯 간 조작 규칙 및 이벤트를 통합 관리하여 중앙 집중식 처리가 가능하게 변경함.
- **결과**: 드래그 앤 드롭 조작 도중 발생할 수 있는 데이터 꼬임 현상을 사전에 전면 차단.

### 7. 에너미 AI 디코이/전투 타겟 분리
- **내용**: 
  - 디코이(미끼) 수류탄 투척 후 에너미가 플레이어를 더 이상 위협으로 간주하지 않거나 복귀 과정에서 이상 거동을 보이는 현상을 진단함.
  - 원인은 디코이 대상을 단일 타겟 변수로 관리하면서 본래 플레이어 전투 대상 정보가 지워지거나 AI 패트롤 조건과 충돌하기 때문으로 판명됨.
  - 이에 플레이어 조준/교전을 담당하는 `currentTarget`과 디코이처럼 우선 유도가 필요한 일시적 타겟을 위한 `aggroTarget`으로 관심사를 분리함.
  - 디코이가 활성화된 동안에는 이동 목표만 디코이 위치로 전환하며, 기존 플레이어 전투 타겟 데이터는 메모리에 유지하도록 함.
- **결과**: 디코이가 소멸되거나 파괴된 즉시, 에너미가 원래 추적하던 플레이어에게 매끄럽게 어그로를 돌려 재협공하는 흐름 완성.

### 8. 에너미 근접 교전 및 레이캐스트 안정화
- **내용**: 
  - 에너미가 플레이어와 초근접 시 정지하거나 공격 직후 이동 방향을 잃어버리는 오작동을 디버깅함.
  - 플레이어 시야 감지용 `Physics.Raycast`가 에너미 자신의 콜라이더 혹은 자식 오브젝트의 충돌체에 먼저 걸려 플레이어를 감지 불가 상태로 인식하는 문제로 식별됨.
  - 이를 해결하기 위해 `Physics.RaycastAll()`을 사용해 경로상의 모든 콜라이더를 획득하고, 본인 및 자식 레이어의 콜라이더를 명시적으로 제외(Filtering)하도록 개정함.
  - 공격 직후 AI 판단 루프가 꼬이지 않도록 일정 시간 동안 직접 추적을 강제하는 보정 타이머를 보충함.
  - 돌진 직후 패트롤 루트 복귀 판정이 성급하게 일어나지 않도록 판단 복귀 반경에 물리적 버퍼 마진을 둠.
- **결과**: 난전 및 근접전 상황에서 에너미 AI 행동의 신뢰성과 자연스러운 움직임 향상.

### 9. 탄환 라인 및 수류탄 비주얼 리소스 적용
- **내용**: 
  - 플레이어 발사 탄환 궤적에 사용될 `M_BulletLine.mat` 머티리얼을 도입함.
  - 피격 성공 여부에 따라 탄환 색상이 부자연스럽게 반전되던 현상을 수정하여, 컨셉에 어울리는 통일된 보라색 계열 비주얼로 정합성을 맞춤.
  - 디코이 수류탄의 2D 스프라이트를 할당하고 투척 시 궤적을 직관적으로 묘사해 줄 TrailRenderer를 설정함.
  - 수류탄 크기가 비정상적으로 부풀어 보이지 않도록 기본 스프라이트 축소 및 스케일 튜닝을 가함.
- **결과**: 사격 및 투척 무기 사용 시 타격감과 비주얼 퀄리티 향상.

### 10. 캐릭터 Shadow 포트레이트 알파값 방식 적용
- **내용**: 
  - 몬스터 포트레이트 겹침 현상과 유사하게 유안 캐릭터 메인 이미지와 섀도우(그림자) 이미지가 중첩 노출되는 문제를 탐색함.
  - 현재 시점에서 카메라 렌더 레이어를 통째로 개편하기에는 리스크가 큼에 따라, 임시 대안으로 섀도우 포트레이트의 알파(Alpha)를 0으로 강제하는 완화 조치를 도입함.
  - `AnimatorShadowSync`에서 섀도우 AnyPortrait 컴포넌트 자체를 비활성화(Disable)하면 애니메이터 동기화가 끊겨 포즈가 굳어버리므로, 컴포넌트는 살려두고 `SetMeshAlphaAll(0)`을 호출해 렌더링 측면에서 보이지 않게 처리함.
- **결과**: 애니메이션 포즈 동기화를 유지하면서 지저분한 이중 겹침 현상을 안정적으로 완화함.

- 캐릭터 Shadow 포트레이트 메쉬의 알파를 0으로 숨겨둔 조치는 임시 픽스입니다. 나중에 섀도우 연출(그림자 자체의 실시간 묘사 등)의 중요도가 높아진다면 카메라 렌더 레이어 설계 자체를 손봐야 합니다.
- 튜토리얼 팝업 등 UI 프레임 이미지의 나인슬라이스(9-Slice) 적용 여부에 대해 디자이너와 협의가 필요합니다.
- 창고 내 레어리티 프레임의 경우, 런타임 생성 로직과 프리팹 템플릿 구조가 공존하므로 인게임 다양한 등급 아이템들을 반복 루팅/장착하며 추가 검수가 필요합니다.
- 디코이 미끼 소멸 이후, 어그로 타겟이 초기화되었을 때 플레이어에게 정상 회귀하여 사격을 개시하는지 장시간 AI 반복 테스트가 요망됩니다.
- 수류탄 TrailRenderer의 너비(Width) 및 유지 시간(Time) 값은 기획 피드백을 통해 세부 밸런스 조정의 여지가 있습니다.

## 💡 배운 점

- **이벤트 라이프사이클 관리**: UI의 생성 타이밍과 데이터 복원 시점의 미묘한 차이로 인해 이벤트가 누락되는 이슈는 빈번하므로, **직접 1회 동기화**와 **이벤트 수신기**를 병행하는 이중 방어 코딩 방식이 유효함을 재확인함.
- **슬롯 데이터 격리**: 다수의 장착형/인벤토리형 슬롯들이 데이터를 교환할 때는 통합 매니저(`StorageInventoryUI` 등)를 통해 조작 유효성 규칙을 한곳에서 중앙 제어하는 것이 상태 일관성 유지에 훨씬 안전함.
- **AI 우선순위의 독립성**: 임시 유도 대상(디코이 등)과 핵심 공격 목표를 단일 타겟 변수로 덮어씌워 처리할 경우 상태 복구 시점에 정보 손실이 일어남. 다중 상태를 유지하기 위해 변수를 분리해 두는 것이 복구 메커니즘 설계의 기본임을 배움.
- **동적 컴포넌트 제어**: 렌더링을 끄기 위해 컴포넌트 자체를 Disable 시키는 것보다 메쉬 알파나 렌더러를 끄는 것이, 해당 스크립트에 묶인 애니메이터의 업데이트 흐름을 해치지 않고 연출만 조절하는 유용한 우회책이 될 수 있음.
