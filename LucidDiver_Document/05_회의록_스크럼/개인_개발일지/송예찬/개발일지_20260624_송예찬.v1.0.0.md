## ✅ 완료한 작업

### 1. `ItemBox` 역할 변경 및 데이터 저장 구조화
- **내용**: 
  - 플레이어가 상자와 상호작용할 때 즉시 바닥에 아이템을 생성하고 상자가 파괴되던 기존 로직을 제거했습니다.
  - 상자 내부에 아이템 데이터(`BoxItemEntry`)를 리스트 형태로 직접 보유하여 유지되도록 변경하였습니다.
- **결과**: `List<BoxItemEntry> items` 구조를 채택하여 상자가 사라지지 않고 내부 보관함 역할을 수행하는 컨테이너 구조의 기반을 확보했습니다.

### 2. 상자 아이템 데이터 및 랜덤 루팅 옵션 분리
- **내용**:
  - **`BoxItemEntry` 클래스**: 상자 내부의 특정 슬롯 1칸을 표현하는 데이터 클래스로, `ItemData` 에셋 레퍼런스와 아이템 수량(`amount`)을 포함합니다.
  - **`BoxLootOption` 클래스**: 인펙터에서 상자 생성 시 랜덤 획득 후보군(아이템 에셋, 등장 가중치, 최소/최대 수량)을 조정할 수 있는 설정 클래스입니다.
- **결과**: 상자 생성 시점(`useRandomLoot == true`)에 `lootOptions`의 가중치를 계산하여 내부 `items` 데이터를 자동으로 빌드하는 `GenerateRandomItems()` 기능 처리가 가능해졌습니다.

### 3. 체스트 UI (`ChestUI` & `ChestSlotUI`) 신규 구현
- **내용**:
  - 상자의 보유 아이템을 시각적으로 렌더링하고 유저 입력을 처리하는 UI 프레임워크를 개발했습니다.
  - 상자 내부의 아이템 종류 수에 맞춰 동적으로 `ChestSlotUI`를 생성하고, 개별 아이템 아이콘 및 수량을 새로고침(`RefreshAll()`)하도록 연동했습니다.
- **결과**: 좌측 인벤토리, 우측 체스트 UI의 이중 배치 레이아웃 구현 및 비주얼 피드백 시스템을 준비했습니다.

### 4. 우클릭 이동 로직 및 `PlayerInventory.AddItem()` 고도화
- **내용**:
  - 체스트 슬롯 우클릭 감지 시 `ChestUI.TryMoveToInventory(slotIndex)`를 실행합니다.
  - `PlayerInventory.AddItem()`이 아이템 스택 누적 및 빈 슬롯 삽입 후 **실제로 인벤토리에 들어가지 못하고 남은 수량**을 정확하게 반환하도록 로직을 수정했습니다.
- **결과**: 인벤토리가 가득 찰 경우 수용 가능한 만큼만 인벤토리로 이동하고, 남은 수량은 상자에 그대로 유지되는 정밀한 파밍 이동 처리를 구현했습니다. 아이콘 비동기 로드 이후에도 UI 갱신 이벤트가 올바르게 재전파됩니다.

### 5. `InventoryPresenter` 및 입력 액션맵 제어 통합
- **내용**:
  - `InventoryPresenter`가 상자 오픈 이벤트(`OnItemBoxOpened`)를 구독하여 상자 UI와 인벤토리 UI를 동시에 개폐 및 동기화하도록 중재자 패턴을 확장 적용했습니다.
  - 상자가 열렸을 때 `LocalInputReader`를 통해 액션맵을 `UI` 모드로 전환하여 조작계 혼선을 차단하고, 닫힐 때 다시 `Player` 액션맵으로 복귀시킵니다.
- **결과**: UI 연동 상태에서의 마우스 커서 활성화 및 플레이어 조작 잠금 처리를 안정적으로 수행합니다.

## 🔄 진행 중인 작업 (아직 남아 있는 작업)
- **드래그 앤 드롭(Drag & Drop)**: 마우스 드래그를 이용한 인벤토리 ↔ 체스트 슬롯 간 직접적인 아이템 이동 기능 구현.
- **인벤토리 포화 시 바닥 드롭 처리**: 상자와 인벤토리가 모두 가득 찬 상태에서 아이템 이동 시, 초과분이 월드 바닥에 프리햅 형태로 드롭되는 예외 처리.
- **단축키 UI 닫기 바인딩**: `F` 키 또는 `ESC` 키 입력 시에도 UI 액션맵 바인딩을 통해 통합 UI 창이 정상적으로 닫히도록 입력 매핑 검증.
- **테스트용 상자 프리셋 설정**: 인스펙터 상에서 `items` 또는 `lootOptions`에 드롭 프리팹(`_Drop.prefab`) 대신 `ItemData` 에셋(`testHealMedicine.asset` 등)이 올바르게 할당되도록 점검 및 조율.

## ⚠️ 주의 사항 및 핵심 규칙
> [!WARNING]
> **아이템 데이터 레퍼런스 규칙**
> - 상자 내부에 직접 설정하는 데이터는 월드 드롭용 프리팹(예: `testHealMedicine_Drop.prefab`)이 절대 아니어야 합니다.
> - 반드시 데이터 정보만을 담고 있는 **`ItemData` ScriptableObject 에셋(예: `testHealMedicine.asset`, `testManaPiece.asset`, `testMemoryPiece.asset`)**을 직접 바인딩해야 정상 작동합니다.
