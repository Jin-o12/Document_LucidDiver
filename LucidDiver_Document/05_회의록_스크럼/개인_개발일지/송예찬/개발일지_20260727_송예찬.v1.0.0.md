## ❗ 이슈 및 블로커

- 게임 세션이 시작될 때 꿈식자가 이미 스폰되어 있어 스폰 시작 장면을 게임 뷰만으로 명확하게 촬영하기 어려웠습니다. Unity 씬 뷰와 게임 뷰를 함께 사용해 스폰 지점과 실제 순찰 시작을 연결해 보여주는 방식으로 보완했습니다.
- 모든 상태 패널을 개별적으로 열어 설명하면 제한 시간을 초과하므로, 3분 발표에서는 순찰·조사·공격 등 대표 사례만 직접 조작하고 나머지는 전체 FSM 화면에서 묶어 설명하도록 범위를 줄였습니다.
- `presentation.html`은 최종 발표 담당자가 관리하는 고정 발표본이므로 직접 수정하지 않고, 필요한 자료와 배치 지침을 개인 발표 자료 MD에 기록합니다.

## 🛠️ 트러블 슈팅 (선택)

1. **문제 상황**: 촬영 영상의 행동 구간과 발표 대본의 설명 순서가 일치하지 않거나, 상태 전환이 너무 빠르게 지나가 청중이 행동의 의미를 확인하기 어려웠습니다.
2. **발생 조건**: 게임 플레이를 연속으로 녹화하면 여러 AI 상태가 짧은 간격으로 바뀌고, 게임 뷰만으로는 감지 범위·소음 앵커·순찰 경로 같은 판단 근거가 보이지 않았습니다.
3. **해결 방법**: 행동별 구간을 다시 선별하고 게임 뷰와 씬 뷰를 병행했습니다. 대본에는 화면 조작과 발화를 분리해 기록하고, 전체 루프 설명 후 대표 상태만 확대하는 순서로 재구성했습니다.
