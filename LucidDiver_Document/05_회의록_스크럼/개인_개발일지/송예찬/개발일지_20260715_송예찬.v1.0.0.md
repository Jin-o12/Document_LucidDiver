## ✅ 완료한 작업

### 1. 튜토리얼 단계 구조 재정리
- **내용**: 
  - 튜토리얼 진행 단계를 1~6단계로 다시 정리함.
  - 1단계(이동 기본), 2단계(전투 조작 사전 안내), 3단계(전투 실습), 4단계(상자/아이템 루팅), 5단계(상자 내부 아이템/아티팩트 설명), 6단계(포탈/탈출)로 구분.
  - 5단계의 경우 물리 콜라이더가 아닌 실제 상자 UI가 열린 시점의 이벤트 기반 단계로 정의함.
  - 씬 트리거 구조를 `Trigger_TutorialStep1`, `Trigger_TutorialStep2`, `Trigger_TutorialStep3`, `Trigger_TutorialStep4`, `Trigger_TutorialStep6`으로 최적화함.
- **결과**: 직관적이고 끊김 없는 단계별 튜토리얼 흐름 구축 완료.

### 2. JSON 기반 튜토리얼 안내 데이터 구성
- **내용**: 
  - `TutorialGuide.json`을 기준으로 안내 문구, 열림 조건, 클리어 조건, 다음 안내 ID를 통합 관리하도록 구성함.
  - `TutorialGuideData` 클래스를 구현하여 JSON의 개별 데이터 행을 객체 단위로 핸들링함.
  - `LocalJsonTutorialGuideRepository`가 `Resources/JSON/TutorialGuide.json`을 읽어 런타임에 튜토리얼 데이터를 로드하도록 함.
  - `TutorialConditionTypes`에 조건 문자열 및 이벤트명을 상수로 정리함.
- **결과**: 기획 데이터 조정을 통해 유연하게 안내 문구와 조건을 변경할 수 있도록 코드와 데이터를 분리 완료.

### 3. TutorialManager 흐름 확장
- **내용**: 
  - 기존 카탈로그 기반의 단순 팝업 구조에서 JSON 조건 기반의 순차 진행 구조로 시스템을 확장함.
  - 콜라이더 진입은 `NotifyTriggerEnter()`로, 상자 개방/적 처치/탈출 성공 등의 행동 이벤트는 `NotifyEvent()`로 받도록 이원화 처리함.
  - 현재 팝업이 노출 중일 때 다음 안내가 들어오면 큐(Queue)에 보관했다가 순차적으로 출력되도록 제어함.
  - 이미 출력된 안내는 `openedGuideIds`를 통해 중복 출력을 방지함.
  - `PrevGuideClosed`, `NextButton`, `Event`, `TriggerEnter` 등의 조건을 세분화하여 연출 순서의 정확성을 확보함.
- **결과**: 다양한 트리거와 조건이 얽힌 복합적인 튜토리얼 상황에서의 연출 안정성 확보.

### 4. 상자 루팅 / 아이템 설명 흐름 분리
- **내용**: 
  - 상자 근처에 접근했을 때는 F 키 상호작용 안내를 출력함.
  - 실제 상자를 열었을 때 `ItemBoxOpened` 이벤트를 발생시켜 상자 UI 내부 안내로 연결되도록 함.
  - 상자 UI 내부에서는 아이템 슬롯 확인, 마우스 오버 툴팁, 더블클릭/드래그 앤 드롭, 퀵슬롯/아티팩트 장착 설명 등이 흐름에 맞춰 단계적으로 노출되도록 구성함.
- **결과**: 단순 위치 도달과 실제 액션 완료의 책임을 명확히 구분하여 기획 의도를 정교하게 반영.

### 5. 탈출 후 결과창 흐름 정리
- **내용**: 
  - 튜토리얼 탈출 성공 즉시 로비 씬으로 직접 이동하던 구식 흐름을 제거함.
  - 인게임 메인 플레이 흐름과 동일하게 탈출 성공 후 결과창이 먼저 표시되고, 결과창의 로비 버튼을 클릭할 때 로비로 이동하도록 구조를 개선함.
  - `TutorialManager`와 `TutorialCompletionTrigger`는 세이브 데이터 내 `isTutorialCompleted` 플래그의 저장 역할만 수행하도록 책임을 한정함.
  - 실제 로비 이동은 `ResultUI`의 기존 `OnGoToLobbyScene` 로직을 타도록 통합함.
- **결과**: 튜토리얼과 인게임 세션 정산 흐름의 시스템 정합성 일치.

### 6. 인트로 튜토리얼 진입 옵션 정리
- **내용**: 
  - `IntroSceneController`의 `useTutorialScene` 옵션으로 튜토리얼 씬 진입 여부를 제어하도록 함.
  - 개발 및 QA 테스트 편의를 위해 `resetTutorialCompletedOnIntro` 개발용 옵션을 새로 추가함.
  - 해당 옵션 활성화 시, 인트로 진입 단계에서 `SaveFile.json`의 `isTutorialCompleted` 플래그를 자동으로 false로 되돌려줌.
- **결과**: 전체 세이브 파일을 매번 수동으로 삭제해야 했던 번거로움을 해결하고 반복 테스트 효율성 대폭 증대.

### 7. 베타 병합 후 로컬 변경 원인 분석
- **내용**: 
  - 베타 브랜치 머지 이후 로컬 저장소에서 예기치 않은 변경 사항(대량 삭제 및 되돌림)이 감지되어 분석을 진행함.
  - 분석 결과, 정상적인 신규 작업의 누적이 아닌 이미 완료되어 머지된 튜토리얼의 최신 구현체가 유실되고 이전 카탈로그 기반 구조로 되돌아가는 디그레이션(Degradation) 현상임을 확인 함.
  - 구체적으로 `TutorialGuide.json`, `TutorialGuideData.cs`, `TutorialConditionTypes.cs`, `LocalJsonTutorialGuideRepository.cs`가 로컬에서 삭제 상태로 감지되고 있었음.
- **결과**: 머지 꼬임이나 비의도적인 변경 사항이 공용 브랜치에 그대로 커밋 및 푸시되지 않도록 선제 조치 및 확인 작업 대기.

## ❗ 이슈 및 주의할 점
- **개발 옵션 해제 필수**:
  - `resetTutorialCompletedOnIntro` 옵션은 개발 및 내부 테스트 전용이므로 정식 빌드 및 배포 시에는 반드시 false로 꺼져 있는지 확인해야 함.
- **키값 정합성 유지**:
  - `TutorialGuide.json`에 정의된 `OpenConditionValue`와 씬 하이라키 내 트리거의 `triggerValue` 문자열이 오타 없이 정확히 일치해야 함.
- **이벤트 구독 보존**:
  - 상자 내부 설명은 상자 UI가 닫히지 않고 정상적으로 열려 있어야 전개되므로 `ItemBoxOpened` 이벤트의 정상 구독/해제 구조 유지가 필요함.
- **결과창 조기 종료 방지**:
  - 탈출 연출 및 결과창 점수/정보 정산이 모두 끝난 후에 로비 씬으로 넘어가도록 순서 제어가 꼬이지 않아야 함.
- **로컬 diff 관리**:
  - 베타 머지 과정에서 Unity 자동 저장 등으로 코드가 이전 구버전으로 롤백될 뻔한 이슈가 있으므로, `git diff --stat` 명령을 통해 변경 목록을 상시 더블 체크해야 함.
