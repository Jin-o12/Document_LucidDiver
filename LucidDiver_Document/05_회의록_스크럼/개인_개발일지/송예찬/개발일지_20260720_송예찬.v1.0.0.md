## ✅ 진행한 작업

### 1. 병합 후 입력·프리팹 참조 복구
- `InputManager`가 아직 준비되지 않았거나 비활성화된 `PlayerInput`을 직접 참조해 예외가 발생하지 않도록 방어 로직을 보강했습니다.
- 액션 맵과 입력 액션을 이름으로 조회할 때 존재 여부를 확인하고, 누락 상태를 경고로 남길 수 있게 했습니다.
- `LocalInputReader`의 입력 차단 상태와 중앙 `InputManager` 경유 액션 맵 전환 흐름을 복구했습니다.
- 중앙 입력 관리자가 준비되지 않은 상황에서만 `PlayerInput` 직접 전환을 fallback으로 사용하도록 정리했습니다.
- 공격, 상호작용, 퀵슬롯 입력 이름과 구독 흐름을 현재 Input Actions 구조에 맞췄습니다.
- `Player_Yuan` 프리팹에서 유실된 `LocalInputReader` 계열 참조와 `UI-InventorySlot.prefab`의 드래그 영역을 복구했습니다.

### 2. 튜토리얼 입력 누수와 VFX 풀 안정화
- 튜토리얼 또는 인벤토리 UI가 열린 동안 이동, 공격, 스킬, 상호작용, 퀵슬롯 입력이 게임플레이로 전달되지 않도록 보강했습니다.
- 튜토리얼 확인 버튼을 누른 클릭이 팝업 종료 직후 총 발사로 이어지지 않도록 입력 복귀를 2프레임 지연했습니다.
- VFX가 `OnDisable`에서 풀로 반환될 때 다시 `SetActive(false)`를 호출하던 흐름을 분리했습니다.
- 같은 VFX가 대기열에 중복 등록되지 않도록 반환 예약 Set을 추가했습니다.
- `OnDisable` 처리 중 부모 변경을 즉시 수행하지 않고, 안전한 시점에 계층과 풀 상태를 복원하도록 정리했습니다.

### 3. 튜토리얼 조작 가이드 하이라이트
- 튜토리얼 JSON 데이터의 `UIHighlightPosition`과 `HighlightEffectPosition`을 실제 강조 표시와 연결했습니다.
- 문자열 ID로 UI 또는 월드 대상을 찾을 수 있도록 `TutorialHighlightTarget` 레지스트리를 추가했습니다.
- 강조 대상 주변만 남기고 화면을 가리는 4분할 암전 패널 구조를 적용했습니다.
- 강조 프레임, 목표 안내 문구, 밝기 펄스를 추가했습니다.
- 게임 시간이 멈춘 상태에서도 강조 애니메이션이 유지되도록 `unscaledTime`을 사용했습니다.
- 가이드 시작·종료, Objective 모드 전환, 강제 종료 시 하이라이트가 함께 정리되도록 `TutorialManager`에 생명주기를 연결했습니다.
- `TutorialSystem`, 상자 UI, Game UI, Inventory UI, ItemTooltip UI 프리팹에 필요한 대상을 연결했습니다.

### 4. Canvas와 스크립트 책임 분리
- 런타임 스크립트가 RectTransform 위치와 크기를 강제로 덮어쓰지 않도록 구성했습니다.
- 위치, 크기, 이미지, 색상 같은 시각 값은 Canvas·프리팹·인스펙터에서 조절하도록 유지했습니다.
- 에디터 설정 도구는 기존 사용자가 조절한 값을 보존하고, 누락된 컴포넌트와 참조만 추가하도록 만들었습니다.
- 튜토리얼 하이라이트와 인벤토리 드롭 피드백 모두 같은 비파괴 설정 원칙을 사용했습니다.

### 5. 인벤토리 장착 가능 슬롯 하이라이트
- 아이템을 드래그할 때 실제로 장착 가능한 슬롯만 밝아지도록 구현했습니다.
- 소비 아이템은 퀵슬롯, 아티팩트는 아티팩트 장착 슬롯에만 놓을 수 있도록 `InventoryItemPlacementPolicy`를 추가했습니다.
- 밝기 오버레이와 옅은 흰색 테두리가 펄스하는 표시 컴포넌트를 추가했습니다.
- `PlayerInventory`, `InventoryPresenter`, `ArtifactEquipSlotUI`, `QuickSlotUI`가 같은 배치 정책을 사용하도록 정리했습니다.
- 시각적으로 허용된 슬롯과 실제 드롭 처리 결과가 다르게 나오는 문제를 방지했습니다.
- 드래그 종료, 취소, 인벤토리 닫기, UI 강제 종료 시 남아 있는 강조를 모두 초기화하도록 했습니다.
- 테스트 플레이에서 장착 가능한 슬롯이 정상적으로 밝아지는 것을 확인했습니다.

### 6. 머즐 플래시 실시간 라이트 적용
- 기존 `PlayerWeapon`의 `VFX_Player_Muzzle` 호출 위치에 `MuzzleFlashLight.PlayFlash()`를 함께 연결했습니다.

- 라이트는 대기 중에는 꺼 두고 발사 순간에만 짧게 활성화하도록 했습니다.

- 최종적으로 HDR 파티클과 짧은 실시간 라이트를 함께 사용하는 방향으로 확정했습니다.

- 머즐 HDR 가시성은 Bloom, FlatKit 픽셀화, 카메라 스택과 렌더러 설정에 따라 달라질 수 있습니다.
- 현재 머즐 라이트의 `peakIntensity = 50`은 `Player_Yuan.prefab`의 직렬화 값이므로 스크립트 기본값과 혼동하지 않아야 합니다.
- 머즐 라이트는 동적 조명이므로 라이트 베이크 대상이 아닙니다.
- `IntroScene`의 튜토리얼 토글 변경과 `TutorialScene` 재직렬화는 머즐 기능의 핵심 변경과 분리해서 봐야 합니다.
- `PlayerCombatPresenter`에는 이후 팀원 변경이 섞였으므로 개인 변경 비교에서는 `2f085c3` 상태를 현재본으로 사용했습니다.
- 튜토리얼 하이라이트는 해상도와 Canvas Scaler가 달라질 때도 강조 위치가 유지되는지 추가 검증이 필요합니다.
- 인벤토리 드래그 취소와 UI 강제 종료 상황에서 강조 잔상이 남지 않는지 반복 확인이 필요합니다.

## 💡 배운 점

- `Time.timeScale = 0`만으로는 UI 클릭이 공격 입력으로 전달되는 현상을 막을 수 없습니다. 게임플레이 입력 상태와 닫힘 직후 프레임까지 함께 관리해야 합니다.
- VFX 풀의 `OnDisable` 반환은 다시 비활성화하거나 즉시 부모를 바꾸는 방식보다, 중복 방지와 지연 복원을 분리하는 편이 안전합니다.
- 드롭 가능 슬롯의 강조와 실제 아이템 이동 검증이 서로 다른 규칙을 사용하면 UI가 플레이어에게 잘못된 정보를 줍니다.
- 자주 조정하는 UI의 위치와 크기는 코드에서 고정하지 않고 인스펙터에 맡겨야 반복 수정 비용이 줄어듭니다.
- 어두운 화면에서 짧은 발사 피드백을 보강할 때는 Light 강도만 올리는 것보다 파티클 HDR 발광과 짧은 Light를 함께 조절하는 편이 효과적입니다.
- 여러 VFX가 공유하는 ThirdParty 원본을 직접 수정하면 영향 범위가 커지므로, 플레이어 전용 프리팹을 분리하는 것이 안전합니다.
- 긴 코드 전문 기록은 한 페이지에 모두 몰기보다 기능 인덱스 아래 스크립트별 페이지로 분리해야 읽기와 검증이 쉽습니다.
