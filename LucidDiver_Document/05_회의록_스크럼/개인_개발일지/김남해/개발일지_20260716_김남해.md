## ✅ 완료한 작업

### 1. 플레이어 손전등 구현 — Spot Light 2개 구성

#### 초기 접근 — ProBuilder Cone + ConeBeam

손전등 조명 범위를 시각적으로 표현하기 위해 처음에는 **ProBuilder로 Cone 오브젝트를 생성하고 ConeBeam 효과를 적용하는 방식**을 시도했다.

```
[초기 방식]
ProBuilder Cone 오브젝트
  └─ ConeBeam 컴포넌트
     → 손전등 빛줄기 영역을 메시로 시각화
```

**문제점 — 벽 관통**

ConeBeam 메시가 벽 콜라이더를 인식하지 못하고 벽을 그대로 통과하여 렌더링되었다. 플레이어가 벽 가까이 서 있으면 빛줄기가 벽 너머까지 표시되어 공간 구조가 노출되는 문제가 발생했다.

#### 최종 방식 — Spot Light 2개 분리 배치

ConeBeam 방식을 포기하고 Unity 기본 **Spot Light 두 개를 사용하는 방식**으로 변경했다. Spot Light는 URP Shadow를 통해 벽에 의해 자연스럽게 차단되므로 관통 문제가 발생하지 않는다.

| 광원 | 역할 | 조명 방향 | 특징 |
|:---|:---|:---:|:---|
| Flashlight_Front | 정면 조명 | 캐릭터 정면 | 원거리 탐색용, 좁은 Spot Angle |
| Flashlight_Ground | 발밑 조명 | 바닥 방향 | 근거리 발밑 밝기 보정, 넓은 Spot Angle |

```
Player
└─ FlashlightAnchor
   ├─ Flashlight_Front  (Spot Light — 정면)
   └─ Flashlight_Ground (Spot Light — 바닥)
```

**이점:**

- 벽에 의해 광원이 자연스럽게 차단됨 (Shadow 활용)
- 바닥 광원으로 발밑 공간의 시인성 확보
- ProBuilder 메시 없이 순수 광원만으로 구성되어 드로우콜 절감

### 2. 문 상호작용 — F키 GuideUI 추가

기존에 구현되어 있던 문 상호작용 기능에 플레이어가 문 앞에 접근했을 때 **"F — 열기 / 닫기"** 안내를 표시하는 GuideUI를 추가했다.

#### 구현 방식

GuideUI는 Camera Overlay가 아닌 **World Space Canvas**로 구성하여 문 오브젝트에 종속된 위치에 배치했다.

```
Door
└─ DoorInteractUI (Canvas — World Space)
   └─ GuideText ("F — 열기")
```

플레이어가 상호작용 범위(`Trigger Collider`)에 진입하면 UI를 활성화하고, 범위를 벗어나면 비활성화한다.

## ❗ 이슈 및 블로커

### [미해결] GuideUI — World Space 렌더링 문제

#### 현상

GuideUI를 World Space Canvas로 구성한 결과, 두 가지 문제가 발생하고 있다.

| # | 현상 | 설명 |
|:---:|:---|:---|
| 1 | **UI가 문과 함께 움직임** | 문이 열리고 닫힐 때 Canvas가 문 오브젝트의 자식으로 종속되어 있어 UI도 함께 회전·이동함 |
| 2 | **UI가 벽에 가려짐** | World Space 오브젝트이므로 뎁스 순서에 따라 벽·문에 의해 UI가 가려짐 |

#### 원인 분석

Camera Overlay (Screen Space — Camera 또는 Screen Space — Overlay) 방식의 UI는 항상 화면 최상단에 렌더링되므로 위 문제가 발생하지 않는다. 그러나 현재 GuideUI를 World Space로 구성한 이유는 문마다 독립적인 위치에 UI를 표시하기 위함이었다.

```
[World Space Canvas의 문제 구조]

Door (열림/닫힘 애니메이션 → Transform 변화)
└─ DoorInteractUI (Canvas — World Space)
   → 문 Transform의 영향을 받아 UI도 함께 이동·회전
   → 씬의 다른 오브젝트와 뎁스 경쟁 → 벽/문에 의해 가려짐
```

#### 논의 필요 — 해결 방향 후보

아래 방향들에 대해 팀 논의가 필요하다.

**Option A — World Space Canvas를 문의 자식에서 분리**

UI Canvas를 문의 자식 계층에서 분리하여 씬 루트에 독립 배치하고, 스크립트로 문 위치를 추적하여 UI 위치를 매 프레임 업데이트한다. UI가 문과 함께 움직이는 문제는 해결되지만, 벽에 가려지는 문제는 여전히 남는다.

```
[Scene Root]
└─ DoorInteractUI (Canvas — World Space, 분리)
   → 스크립트로 문 Transform.position을 추적

Door (자식 계층에서 UI 제거)
```

**Option B — Screen Space — Camera Canvas로 전환**

World Space를 포기하고 Screen Space — Camera 방식으로 전환한다. 문의 World Position을 `Camera.WorldToScreenPoint()`로 변환하여 스크린 좌표로 UI 위치를 지정한다.

- 벽 관통 가려짐 문제와 문 회전 문제 모두 해결 가능
- 다만 여러 문이 동시에 범위에 들어올 경우 UI 위치 관리 로직이 복잡해질 수 있음

**Option C — Always On Top 렌더링 설정**

Canvas의 `Sort Order` 또는 별도 `Overlay Camera`를 추가하여 UI가 항상 최상단에 렌더링되도록 설정한다. UI 위치 문제(문과 함께 이동)는 별도 처리 필요.

> **결론**: 현재 미해결 상태. 세 가지 옵션에 대한 팀 논의 후 방향 결정 필요.

## 🛠️ 트러블슈팅

### 1. ConeBeam 메시가 벽을 관통하는 문제

- **현상**: ProBuilder Cone + ConeBeam으로 만든 손전등 빛줄기가 벽 콜라이더를 무시하고 벽 너머까지 렌더링됨
- **원인**: ConeBeam은 메시 기반 시각 효과로, 물리 콜라이더와 상호작용하지 않음. 벽의 콜라이더가 메시 렌더링을 차단하지 못함
- **해결**: ConeBeam 방식을 포기하고 Spot Light 2개로 대체. Spot Light는 URP Shadow를 통해 벽에 의해 자연스럽게 차단됨
