## ✅ 완료한 작업

### 1. 책임 분리 구조 — OcclusionDetector / OcclusionWall 2-스크립트 설계

가림 감지 로직과 머티리얼 교체 로직을 단일 스크립트에 모으지 않고 역할에 따라 분리하였다.

| 스크립트 | 부착 위치 | 역할 |
|:---|:---|:---|
| `OcclusionDetector` | 카메라 오브젝트 | SphereCast로 가림 벽 감지, `OcclusionWall.SetOccluded()` 호출 |
| `OcclusionWall` | 벽 프리팹 루트 | 머티리얼 교체 및 알파 페이드 자체 처리 |

카메라 쪽은 "무엇이 가리고 있는가"만 판단하고, 벽 쪽은 "어떻게 투명해질 것인가"만 담당하도록 역할을 분리함으로써, 각 스크립트의 수정 이유가 하나로 한정된다.

### 2. OcclusionDetector — SphereCast 기반 가림 벽 감지

#### 핵심 설계 결정

- **`Physics.SphereCastNonAlloc` 채택**: `SphereCastAll`은 매 호출마다 `RaycastHit[]` 배열을 힙에 새로 할당한다. `NonAlloc` 버전은 `Awake`에서 미리 할당한 `hitBuffer` 배열을 재사용하므로 GC Alloc이 발생하지 않는다.
- **`[DefaultExecutionOrder(100)]`**: 캐릭터 이동 스크립트보다 늦게 실행되도록 실행 순서를 뒤로 미뤄, `LateUpdate`에서 최신 플레이어 위치를 기준으로 캐스팅한다.
- **`LateUpdate`에서 감지 실행**: 캐릭터 이동이 완료된 이후 시점에 감지하기 위해 `LateUpdate`를 사용한다.
- **`QueryTriggerInteraction.Collide`**: 벽 오브젝트에 별도의 `OcclusionVolume` 트리거 콜라이더를 두고, SphereCast가 해당 트리거에도 반응하도록 설정하였다.

#### 플레이어 연결 — GlobalEventBus 이벤트 구독

플레이어는 런타임에 `SpawnManager`가 생성하므로 Inspector에서 직접 연결할 수 없다. `GlobalEventBus`의 이벤트를 구독하여 생성/제거 시점에 자동으로 연결·해제한다.

```
OnEnable  → GlobalEventBus.OnPlayerSpawned  구독
           → GlobalEventBus.OnPlayerDespawned 구독
Start     → TryBindExistingPlayer() (카메라보다 플레이어가 먼저 생성된 경우 대비)
OnDisable → 이벤트 구독 해제 + 모든 벽 복원
```

#### 감지 파라미터

| 파라미터 | 기본값 | 설명 |
|:---|:---:|:---|
| `sphereRadius` | `0.35f` | SphereCast 반경 |
| `playerHeightOffset` | `1f` | 피벗이 발에 있는 캐릭터의 몸통 높이 보정 |
| `wallLayerMask` | Inspector 설정 | 벽 콜라이더 레이어 |
| `maxHitCount` | `32` | 버퍼 크기 (힙 재할당 없이 최대 감지 수) |

#### HashSet 스왑 패턴으로 프레임 간 비교

```csharp
// 교체 전: activeWalls = 지난 프레임 감지 목록, detectedWalls = 이번 프레임 감지 목록

foreach (OcclusionWall wall in activeWalls)
    if (!detectedWalls.Contains(wall)) wall.SetOccluded(false); // 해제

foreach (OcclusionWall wall in detectedWalls)
    if (!activeWalls.Contains(wall)) wall.SetOccluded(true);  // 신규 가림

// 두 HashSet을 참조 교환하여 다음 프레임 비교에 재사용한다 (추가 할당 없음)
(activeWalls, detectedWalls) = (detectedWalls, activeWalls);
```

### 3. OcclusionWall — 머티리얼 교체 및 알파 페이드

#### 문제 상황 — Opaque 머티리얼의 알파 미지원

맵에 적용된 FlatKit 머티리얼은 렌더 타입이 **Opaque**로 설정되어 있어, 런타임에서 단순히 알파값(`Color.a`)을 낮추어도 투명도가 적용되지 않는다.

| 방식 | 문제점 |
|:---|:---|
| Opaque 머티리얼의 `_Color.a` 직접 수정 | 렌더 타입이 Opaque이므로 알파값 무시됨 — 효과 없음 |
| 런타임에서 렌더 타입을 Transparent로 변경 | FlatKit 쉐이더 내부 Pass 구조와 충돌, Renderer Feature 호환성 문제 |

#### 해결 — ShaderGraph 기반 Fade 머티리얼 + MaterialPropertyBlock

ShaderGraph로 `Surface Type: Transparent`, `Blend: Alpha`로 설정된 전용 머티리얼을 제작하고, 알파값은 `MaterialPropertyBlock`으로 개별 Renderer마다 독립적으로 제어한다.

```
[ShaderGraph 구성]
 Fragment Node
  ├─ Base Color : Color 또는 Texture
  └─ Alpha      : _BaseColor.a (PropertyBlock으로 런타임 제어)

 Graph Settings
  └─ Surface Type : Transparent
  └─ Blend Mode   : Alpha
```

> `renderer.sharedMaterials`를 사용하면 씬 전체의 같은 머티리얼이 동시에 변경된다. 따라서 알파 값은 `MaterialPropertyBlock`으로 Renderer 인스턴스 단위로만 덮어쓴다.

#### RendererRuntimeData — 렌더러별 데이터 일괄 관리

각 Renderer의 원본 Opaque 머티리얼과 Fade 머티리얼의 기준 색상(`fadeBaseColors`), 그리고 슬롯별 `MaterialPropertyBlock`을 하나의 내부 클래스로 묶어 관리한다.

```csharp
private sealed class RendererRuntimeData
{
    public Renderer renderer;
    public Material[] opaqueMaterials;   // 복원용 원본 sharedMaterials
    public Color[] fadeBaseColors;       // Fade Material의 RGB 원본값 보존
    public MaterialPropertyBlock[] propertyBlocks; // 슬롯별 Alpha 적용용
}
```

#### LOD Group 자동 수집

`wallRenderers`가 비어 있을 경우, `LODGroup.GetLODs()`로 LOD 0~2의 모든 Renderer를 자동으로 수집한다. LOD Group도 없으면 `GetComponentsInChildren<Renderer>()`로 폴백한다.

#### 투명화 및 복원 흐름

```
SetOccluded(true) 호출
  → sharedMaterials를 Fade Materials로 교체
  → isUsingFadeMaterials = true
  → Update에서 currentAlpha를 fadedAlpha(0.25f)로 MoveTowards
  → MaterialPropertyBlock으로 슬롯별 _BaseColor / _Color Alpha 적용

SetOccluded(false) 호출
  → isOccluded = false
  → Update에서 currentAlpha를 1f로 MoveTowards
  → currentAlpha ≈ 1f 도달 시 RestoreOpaqueMaterialsImmediate() 호출
  → sharedMaterials를 opaqueMaterials로 복원
  → 각 슬롯에 SetPropertyBlock(null) 호출하여 PropertyBlock 제거
```

#### 페이드 파라미터

| 파라미터 | 기본값 | 설명 |
|:---|:---:|:---|
| `fadedAlpha` | `0.25f` | 가림 상태의 최소 알파 |
| `fadeSpeed` | `3f` | 초당 알파 변화량 (`MoveTowards` 속도) |

### 4. 최종 동작 흐름 정리

```
[LateUpdate — OcclusionDetector]
  1. SphereCastNonAlloc 실행 (Camera → Player + playerHeightOffset)
  2. hitBuffer에서 OcclusionWall 컴포넌트 탐색 (GetComponentInParent)
  3. detectedWalls와 activeWalls 비교
     ├─ 신규 가림 → OcclusionWall.SetOccluded(true)
     │    └─ sharedMaterials → Fade Materials 교체
     └─ 감지 해제 → OcclusionWall.SetOccluded(false)
          └─ 알파가 1f에 도달하면 sharedMaterials → Opaque Materials 복원

[Update — OcclusionWall]
  - 매 프레임 currentAlpha를 targetAlpha로 MoveTowards
  - MaterialPropertyBlock으로 슬롯별 알파 적용
```

## 🛠️ 트러블슈팅

### Opaque 머티리얼 — 런타임 알파 제어 불가 문제

- **현상**: `renderer.material.color = new Color(r, g, b, 0.3f)`로 알파값을 설정했으나, 벽이 전혀 투명해지지 않음
- **원인**: FlatKit 머티리얼의 렌더 타입이 `Opaque`로 고정되어 있어 알파 채널 자체를 렌더링 파이프라인이 무시함. URP의 Opaque Pass는 알파 블렌딩을 수행하지 않음
- **시도한 방법**:
  - `material.SetFloat("_Surface", 1)` (Transparent 전환 키워드) — FlatKit 쉐이더에서 동작하지 않음
  - `material.renderQueue = (int)RenderQueue.Transparent` 단독 설정 — 효과 없음
- **최종 해결**: ShaderGraph로 `Surface Type: Transparent`, `Blend: Alpha`로 설정된 별도 Fade 머티리얼을 제작하고, `sharedMaterials` 교체 + `MaterialPropertyBlock`으로 알파를 슬롯별 제어하는 방식으로 해결
