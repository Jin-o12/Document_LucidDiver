## ✅ 완료한 작업

### 1. 기존 이동 충돌 처리 방식 분석
- **내용**: 기존 `PlayerMovement`는 `Rigidbody.MovePosition()`으로 목표 위치를 계산한 뒤, 구르기 상태인 `isEvading == true`일 때만 `GetSafeMovePosition()`을 호출하고 있었다. 해당 함수는 `Rigidbody.SweepTest()`와 보조 `SphereCast()`를 사용해 벽 충돌을 검사했다.
- **확인한 한계**:
  - 걷기와 달리기에는 이동 전 경로 검사가 적용되지 않아 이동 속도가 높아질수록 얇은 벽을 한 프레임 안에 넘어갈 가능성이 있었다.
  - `Rigidbody.SweepTest()`는 실제 몸통 충돌체만을 명시적으로 선택하지 못해, 플레이어에 연결된 다른 Collider 구조의 영향을 받을 수 있었다.
  - 벽에 비스듬히 접근했을 때 남은 이동량을 벽면 방향으로 보정하지 않아, 벽 앞에서 완전히 멈추거나 모서리에서 불안정하게 충돌할 가능성이 있었다.
- **결과**: 관통 방지 로직을 구르기 전용 위치 보정이 아닌, 모든 이동 상태에서 공통으로 사용하는 이동량 보정 구조로 변경할 필요성을 확인했다.

### 2. 실제 몸통 이동용 CapsuleCollider 분리
- **내용**: `Collision Guard` 설정에 `movementCollider` 필드를 추가하고, 이동 충돌 검사에 사용할 실제 몸통 `CapsuleCollider`를 별도로 지정하도록 변경했다.
- **구현 사항**:
  - `FindMovementCollider()`를 추가해 플레이어 하위 오브젝트에서 Trigger가 아닌 `CapsuleCollider`를 검색했다.
  - 검색된 Collider가 현재 플레이어 `Rigidbody`에 연결되어 있는지도 확인했다.
  - `Awake()`에서 수동 연결이 누락된 경우 자동 검색을 시도하고, 유효한 Collider를 찾지 못하면 오류 로그를 출력하도록 했다.
  - 상호작용 범위용 Trigger Collider는 이동 충돌 형상에서 제외했다.
- **결과**: 상호작용 범위와 실제 물리 충돌 범위를 분리하여, 넓은 상호작용 Collider 때문에 이동이 과도하게 제한되는 문제를 방지할 수 있는 구조를 마련했다.

### 3. 모든 이동 상태에 CapsuleCast 기반 경로 검사 적용
- **내용**: 기존에는 구르기 상태에서만 목표 위치를 보정했으나, 수정 후에는 걷기·달리기·구르기 모두 동일한 충돌 검사 과정을 거치도록 변경했다.
- **구현 사항**:
  - 입력 방향과 최종 이동 속도로 `desiredMoveDelta`를 계산했다.
  - `ResolveMovementDelta()`에서 실제 이동 가능한 `safeMoveDelta`를 구했다.
  - 보정된 이동량을 현재 `Rigidbody.position`에 더한 뒤 `MovePosition()`으로 적용했다.
  - `TryCastMovement()`에서 실제 몸통 형상의 `Physics.CapsuleCast()`를 실행했다.
  - `movementObstacleMask`와 `QueryTriggerInteraction.Ignore`를 사용해 벽 레이어만 검사하고 Trigger는 제외했다.
  - `movementWallBuffer`만큼 벽과의 안전거리를 남겨 Collider가 벽면에 깊게 겹치지 않도록 했다.
- **결과**: 코드상으로 일반 이동과 달리기에도 연속적인 이동 경로 검사가 적용되어, 고속 이동 시 얇은 벽을 관통할 가능성을 낮췄다.

### 4. 벽면 슬라이딩 및 모서리 재검사 구현
- **내용**: 첫 번째 CapsuleCast에서 벽을 감지하면 즉시 이동을 중단하지 않고, 벽에 닿기 전까지 이동한 뒤 남은 이동량을 벽면 방향으로 투영하도록 변경했다.
- **구현 사항**:
  - 첫 충돌 지점에서 `movementWallBuffer`를 제외한 전진 가능 거리를 계산했다.
  - 남은 이동량을 `Vector3.ProjectOnPlane()`으로 벽의 법선 방향에서 제거해 벽면을 따라 이동하는 `slideDelta`를 계산했다.
  - 슬라이딩 경로에도 두 번째 CapsuleCast를 실행해 벽 모서리나 인접한 다른 벽과의 추가 충돌을 검사했다.
  - 두 번째 충돌이 감지되면 해당 지점 직전까지만 슬라이딩하도록 이동량을 다시 제한했다.
- **결과**: 대각선으로 벽에 접근했을 때 캐릭터가 완전히 멈추는 현상을 줄이고, 벽을 따라 자연스럽게 이동하면서 모서리를 뚫는 현상도 함께 방지할 수 있는 구조를 구현했다.

### 5. CapsuleCollider 월드 형상 계산 보강
- **내용**: `GetMovementCapsule()`을 추가해 Collider의 방향과 Transform Scale이 반영된 월드 좌표 기준 캡슐 양 끝점과 반지름을 계산하도록 했다.
- **구현 사항**:
  - `CapsuleCollider.direction` 값에 따라 X·Y·Z축 방향을 구분했다.
  - `Transform.lossyScale`을 사용해 높이와 반지름의 월드 스케일을 계산했다.
  - Collider 높이가 지름보다 작아지지 않도록 최소 높이를 보정했다.
  - 계산한 `point1`, `point2`, `radius`를 CapsuleCast의 실제 검사 형상으로 사용했다.
- **결과**: 플레이어 프리팹이나 하위 오브젝트에 Scale 또는 Collider Direction 변경이 있어도 실제 몸통 크기와 가까운 충돌 경로 검사가 가능하도록 개선했다.

## ❗ 이슈 및 블로커
- `movementObstacleMask`가 비어 있을 경우 코드가 `Wall` 레이어를 자동으로 사용한다. 프로젝트에 `Wall` 레이어가 없거나 벽 오브젝트의 레이어가 다르면 충돌 보정이 작동하지 않는다.
- 실제 몸통 Collider가 Trigger로 설정되어 있거나 현재 플레이어 Rigidbody에 연결되어 있지 않으면 `FindMovementCollider()`가 Collider를 찾지 못한다.
- 이동 시작 시점부터 플레이어 Collider가 벽과 겹쳐 있는 상황에 대한 별도의 겹침 해소 처리는 현재 코드에서 확인되지 않는다. 해당 상황이 발생하는지는 추가 테스트가 필요하다.

## 🛠️ 트러블 슈팅
1. **문제 상황**: 이동 속도가 높아지거나 구르기를 사용할 때 콜라이더가 맞닿은 모서리와 얇은 벽을 관통하는 문제가 발생했다.
2. **발생 조건**: `Rigidbody.MovePosition()`으로 한 물리 프레임의 이동 거리가 벽 두께보다 커지거나, 벽 모서리에 대각선으로 진입할 때 발생할 가능성이 높았다. 기존 관통 방지 검사는 구르기 상태에서만 실행되고 있었다.
3. **기존 접근의 한계**: `Rigidbody.SweepTest()`와 보조 `SphereCast()`로 목표 위치를 제한했지만 실제 몸통 Collider를 명확하게 선택하지 못했고, 일반 이동에는 적용되지 않았다. 또한 충돌 후 남은 이동량을 벽면 방향으로 처리하지 않았다.
4. **해결 방법**: Trigger가 아닌 실제 몸통 `CapsuleCollider`를 분리하고, 모든 이동 상태에서 해당 형상을 기준으로 `CapsuleCast()`를 실행했다. 첫 충돌 후에는 벽 앞까지 이동하고 남은 이동량을 벽면에 투영했으며, 슬라이딩 경로에 두 번째 충돌 검사를 적용했다.
5. **기대 효과**: 얇은 벽과 모서리 관통 가능성을 낮추면서, 벽에 비스듬히 접근했을 때 이동이 완전히 멈추지 않고 벽면을 따라 자연스럽게 이동할 수 있다. 실제 효과는 Unity 플레이 테스트로 최종 확인해야 한다.
