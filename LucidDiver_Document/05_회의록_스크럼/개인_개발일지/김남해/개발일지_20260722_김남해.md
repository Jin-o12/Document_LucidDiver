## ✅ 완료한 작업

### 1. 창고 & 인벤토리 체크리스트 테스트 및 드래그 앤 드롭 예외 로직 수정 (`StorageInventoryUI.cs`)

- **내용**: 창고, 인벤토리, 안전 금고 시스템에 대한 체크리스트 기반 QA 테스트를 진행하고, 장착 중인 아티팩트 아이템 드래그 앤 드롭 시 발생하는 예외 상황 및 데이터 교환 버그를 수정했다.
- **원인 분석**:
  - 기존 `DropToSlot()`이 드래그 영역(`draggingArea`)과 무관하게 일반 아이템 이동·중첩·교환 로직을 무조건 수행하고 있었다. 이로 인해 장착 중인 아티팩트를 소비 아이템 등 비아티팩트 슬롯 위에 놓았을 때 무조건 교환되어 데이터 정합성이 깨지는 현상이 발생했다.
  - `DropToArtifactSlot()`은 기존 장착 슬롯의 아이템을 인벤토리로 반환할 때 수량을 리터럴 `1`로 강제 설정하고 있어, 이전 데이터 오류로 비아티팩트 아이템이 들어간 경우 수량 1로 인벤토리에 재생성되는 비정상 동작이 관찰되었다.
- **구현 사항**:
  - `DropToSlot()` 메서드 진입 시 `draggingArea == AreaType.Artifact` 조건 분기를 추가하여 전용 핸들러 메서드인 `DropEquippedArtifactToSlot()`으로 이관했다.
  - **`DropEquippedArtifactToSlot()` 메서드 신설**:
    - 장착 슬롯의 원본 데이터가 `ArtifactItemData`인지 1차 검증.
    - **빈 슬롯에 드롭**: 장착 해제 후 해당 슬롯으로 정상 이동.
    - **아티팩트가 있는 슬롯에 드롭**: 빈 슬롯 유무와 관계없이 장착 아티팩트와 타겟 아티팩트를 상호 교환(Swap).
    - **소비 아이템 등 비아티팩트 슬롯에 드롭**: 교환을 차단(`Debug.LogWarning`)하고 양쪽 아이템 데이터 상태를 변경 없이 그대로 유지.
  - **`DropToArtifactSlot()` 메서드 개선**:
    - 기존 장착 슬롯 데이터(`target`)의 `ArtifactItemData` 검증 강화 (`Debug.LogError` 방어 코드 적용).
    - 장착 해제 후 드래그를 시작한 인벤토리 슬롯으로 되돌릴 때 원본 수량(`previousAmount`)을 저장하여 `Mathf.Max(1, previousAmount)`로 원본 수량을 손실 없이 보존.
  - **코드 배치 및 호출 순서 정렬**:
    - `DropToArea()` → `DropToSlot()` → `DropEquippedArtifactToSlot()` → `DropToQuickSlot()` → `SwapQuickSlots()` → `DropToArtifactSlot()` → `SwapArtifactSlots()`
- **결과**:
  - 창고·인벤토리·안전 금고 세 영역에 대해 체크리스트 핵심 4개 검증 항목(빈 슬롯 이동, 아티팩트 간 Swap 교환, 비아티팩트 슬롯 드롭 시 기존 상태 유지, 수량 1 미의도 생성 방지) 모두 수용 기준을 만족함을 최종 확인했다.

## 🛠️ 트러블슈팅

### 1. 장착 아티팩트 드래그 앤 드롭 시 비아티팩트 아이템 교환 및 수량 오작동 문제

1. **문제 상황**: 장착 중인 아티팩트를 소비 아이템이 있는 슬롯으로 드롭했을 때 아티팩트가 소비 아이템을 덮어씌우고, 장착 슬롯의 아이템을 인벤토리로 다시 돌려놓을 때 수량이 1로 강제 복구되는 현상 발생.
2. **발생 조건**: UI 드래그 앤 드롭 조작 시 드래그 시작 지점이 아티팩트 장착 슬롯(`draggingArea == AreaType.Artifact`)인 상태에서 `DropToSlot()` 또는 `DropToArtifactSlot()`이 호출될 때.
3. **원인**:
   - `DropToSlot()`에서 일반 슬롯 이동/중첩/교환 로직을 일률적으로 적용하여 장착 영역 아티팩트에 대한 예외 처리가 누락되어 있었음.
   - `DropToArtifactSlot()`에서 반환 슬롯 생성 시 수량을 `previousTID == 0 ? 0 : 1`로 리터럴 `1`로 고정하여 원본 아이템의 수량 데이터를 분실함.
4. **해결**:
   - `StorageInventoryUI.cs` 내 `DropToSlot()` 시작 지점에 `draggingArea == AreaType.Artifact` 조건 검사를 넣고 `DropEquippedArtifactToSlot()` 메서드로 이관.
   - 타겟 슬롯의 `ItemData` 타입 검사를 통해 (1) 빈 슬롯 이동, (2) 아티팩트 간 Swap, (3) 소비 아이템 대상 드롭 시 작업 취소(`Debug.LogWarning`) 규칙 적용.
   - `DropToArtifactSlot()`에서 기존 `target.amount`를 `previousAmount`로 미리 보관한 뒤 `Mathf.Max(1, previousAmount)`로 원본 수량을 복원하도록 수정.
5. **결과**: 예외적인 드래그 앤 드롭 시도에도 아이템 손실이나 데이터 파손 없이 안정적이고 명확하게 처리됨을 검증함.
