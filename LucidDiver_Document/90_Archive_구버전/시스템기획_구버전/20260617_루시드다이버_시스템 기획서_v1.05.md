# 0. 프로토타입 목표

- 로비 신 목표: 이하의 서브컬처 플레이 최소 루프가 구현 가능한지 검증한다.

    - 뽑기 메뉴에서 메인 캐릭터를 획득해 수집한다.

    - 획득한 메인 캐릭터를 육성 / 편성하고 상호작용을 진행한다.

    - 출격 버튼을 통해 월드 신으로 진입한다.

- 월드 신 목표: 이하의 익스트랙션 플레이 최소 루프가 구현 가능한지 검증한다

    - 플레이어가 2.5D 맵 위에서 움직인다.

    - 기본 공격이 나간다.

    - 적 1종이 플레이어를 따라온다.

    - 아이템 1종을 주울 수 있다.

    - 탈출 지점에 닿으면 결과창이 뜬다.

- 기획서 작성 색인

    - 최소 루프 검증을 위한 프로토타입에 적용하는 수치는 “**프로토타입 볼드**” 양식으로 강조하여 표기한다.

        - 최소 루프 검증을 위한 프로토타입에서만 사용되는 프로토타입 전용 기획 사양은 **`[프로토타입 전용]`**  배너로 표기한다.

    - 최소 루프 검증을 위한 프로토타입에서 구현되지 않는 확장 명세 사양은 `[프로토타입 제외]`  배너로 표기한다.

# 1. 플레이어 캐릭터

## 1.1. 오브젝트 구성

- 플레이어 캐릭터 오브젝트는 이하의 하위 오브젝트로 구성된다.

    - 위치 기준점 (Transform): 플레이어의 위치 및 방향(Y 위, Z 정면) 정보를 계산하는 기준점.

    - 몸통 (Collider): 플레이어↔적, 플레이어↔장애물 간의 접촉 상호작용 발동 여부를 판정하는 기준 영역.

        - 장애물 판정을 위해 Trigger 설정을 비활성화한다.

    - 상호작용 구역 (Collider): 플레이어↔상호작용 가능 오브젝트(무장, 회수품) 간의 상호작용 UI 출력 여부를 판정하는 기준 영역.

        - Trigger 설정을 활성화하여 사용한다.

    - 손 (Transform): 무장 아이템 장착 시 무장 오브젝트가 배치되는 위치 기준점.

        - 공격 방향(vector3): 위치 기준점을 시작점, 손을 끝점으로 하는 방향 벡터.

            - 높이(Unity 좌표계의 Y축) 값을 0으로 초기화한 후 길이 Normalize를 적용하여 사용한다.

## 1.2. 플레이어 상태

- 플레이어 캐릭터는 bool 또는 enum으로 표기되는 상태 값을 갖는다.

    - 재장전 중(`isReloading` : bool): 플레이어가 탄창을 전부 사용하여 재장전 상태인지 확인

    - 생존 상태(`livingState` : enum): 플레이어의 메인 캐릭터 상태를 확인

        - 0: idle `기본`

        - 1: down `빈사`

        - 2: gameover `강제 각성`

        - 3: escape`탈출 중`

        - 탈출 조건 우선 순위는 탈출 중 → 강제각성 순서로 처리한다.

## 1.3. 플레이어 조작

### 1.3.1. 이동

- Input System을 사용하여 플레이어 캐릭터에게 이동 명령을 전달한다.

    - PC 키보드+마우스: WASD 및 화살표(↑←↓→) 조작을 사용하여 이동 명령을 입력한다.

        - 전후좌우(1,0) 및 대각선(0.71,0.71) 방향의 이동 명령을 입력받는다.

        - `[프로토타입 제외]` 입력된 이동 명령에 따라 가상 조이스틱에 드래그 애니메이션을 적용한다.

    - `[프로토타입 제외]` 모바일 터치패드: 화면 왼쪽 하단의 가상 조이스틱을 드래그하여 이동 명령을 입력한다.

        - 가상 조이스틱의 드래그 시작 지점과 드래그 유지 지점 사이의 방향 벡터(Vector2, 길이 Normalize 적용) 값만큼 이동 명령을 입력한다.

- 입력된 이동 명령 값에 플레이어의 이동 속도 및 이동 명령 입력 시간(Time.deltaTime)을 곱한 값만큼 플레이어 캐릭터의 실제 이동을 처리한다.

### 1.3.2. 기본 공격

- Input System을 사용하여 플레이어 캐릭터에게 조준 방향을 전달한다.

    - PC 키보드+마우스: UI Raycast Target이 적용되지 않는 캔버스 영역을 마우스 왼쪽 버튼으로 클릭 시, 플레이어 위치 기준점의 UI Canvas 상 위치와 클릭 지점 사이의 방향 벡터(Vector2, 길이 Normalize 적용)를 조준 방향 값으로 입력한다.

        - `[프로토타입 제외]` 입력된 조준 방향에 따라 가상 조이스틱에 드래그 애니메이션을 적용한다.

    - `[프로토타입 제외]` 모바일 터치패드: 화면 오른쪽 하단의 가상 조이스틱을 드래그하여 조준 방향을 입력한다.

        - 가상 조이스틱의 드래그 시작 지점과 드래그 유지 지점 사이의 방향 벡터(Vector2, 길이 Normalize 적용)을 조준 방향 값으로 전달한다.

- 입력된 조준 방향 벡터를 높이(Y) 값이 0인 Vector3으로 환산한 후, 플레이어 캐릭터의 공격 방향 벡터를 조준 방향 벡터 방향으로 회전시킨다.

- 플레이어 캐릭터 오브젝트의 위치 기준점에서 공격 방향 벡터 방향으로 무장의 발사 가능 사거리 길이만큼 공격 Ray를 출력한다.

- 공격 Ray가 적의 피격 범위 Collider에 접촉하면 무장 아이템 오브젝트의 총구 위치에서 기본 공격 루틴을 실행한다.

    - 이하의 경우 중 어느 것에 해당하는 상태에서는 기본 공격 루틴이 실행되지 않는다.

        - 장착 중인 무장이 없는 경우

        - `재장전 중==true` 상태인 경우

        - 플레이어가 보유한 마나가 기본 공격에 필요한 마나 미만인 경우

        - 이전 기본 공격 루틴 1회 실행 후 경과한 시간이 발사 간격 시간 미만인 경우

### 1.3.3. 오브젝트 상호작용

- 플레이어 캐릭터의 상호작용 구역 Collider에 상호작용 가능한 오브젝트의 Collider가 접촉하면 상호작용 시작 이벤트가 발생한다.

    - 상호작용 시작 이벤트 발생 시 상호작용 버튼이 오브젝트에 출력된다.

    - **`[프로토타입 전용]`상호작용 성공 이벤트 발생 시 `획득물`  값이 1 증가한다.**

        - **`획득물` 값은 신 입장 시 0으로 초기화된다.**

- 상호작용 버튼이 출력된 상태에서 상호작용 키를 입력하여 해당 오브젝트와 상호작용을 실행한다.

    - PC 키보드+마우스: Input System에서 F 키를 “상호작용 실행” 키로 등록하여, F 키 입력 시 상호작용을 실행한다.

    - `[프로토타입 제외]` 모바일 터치패드: 출력된 상호작용 버튼을 터치하여 상호작용을 실행한다.

## 1.5. `[프로토타입 제외]` 지원 캐릭터

메인 캐릭터 이외에 추가로 편성 가능한 캐릭터.

- 지원 캐릭터는 필드에 직접 출현하지 않는다.

- 지원 캐릭터의 스킬 계수 등 계산에 필요한 기본 능력치(최대 체력, 공격력, 방어막, 방어력, 마나, 이동속도)는 메인 캐릭터의 수치에서 가져와 사용한다.

    - 공격력 수치는 메인 캐릭터가 장착한 무장의 수치에서 가져온다.

### 1.5.1. `[프로토타입 제외]` 지원 슬롯

- 지원 캐릭터 리스트에서 지원 캐릭터를 선택하여 지원 슬롯에 배치한다.

    - 지원 슬롯은 최대 2개를 사용한다.

    - 지원 슬롯에 배치하는 지원 캐릭터는 월드 신 외부에서 자유롭게 변경할 수 있다.

- 지원 캐릭터가 배치된 지원 슬롯에 할당된 지원 키를 입력하여 호출 스킬을 사용할 수 있다.

    - 지원 키 입력 시 사용하는 호출 스킬은 지원 캐릭터의 호출 스킬 ID 데이터에서 참조한다.

### 1.5.2. `[프로토타입 제외]` 심상 공명

- 월드 신에 진입한 메인 캐릭터와 지원 슬롯에 편성한 지원 캐릭터의 심상 공명 태그가 정해진 조합을 달성한 경우에 획득할 수 있는 패시브 효과.

    - 심상 공명 태그는 `역할 태그`, `기물 태그`, `소속 태그`로 구분된다.

    - 각 메인 캐릭터 및 지원 캐릭터는 1개 이상의 심상 공명 태그를 가진다.

        - 심상 공명 태그를 2개 이상 보유하는 경우, 역할/기물/소속 태그 구분 중에서는 1개까지만 가질 수 있다.

## 1.6. 호감도

- 호감도는 각 메인 캐릭터 및 지원 캐릭터가 가지는 특수한 누적 값이다.

    - 개별 캐릭터마다 `현재 누적 호감도` 내부 변수 값을 가진다.

- 호감도는 `호감도 레벨`  단계로 구성되며, 각 호감도 레벨마다 `총 레벨업 호감도`  값을 가진다.

    - 호감도 레벨 및 총 레벨업 호감도 값은 모든 캐릭터에서 동일하게 사용하며, [RapportLevel] 테이블에서 관리한다.

    - 총 누적 호감도 값이 각 호감도 레벨마다 정해진 총 레벨업 호감도 값 이상이 된 경우 이하의 호감도 레벨 업 처리를 실행한다.

        - 해당 캐릭터의 현재 호감도 레벨 값이 1 증가한다.

        - 호감도 레벨 판정에 사용하는 총 레벨업 호감도 값을 증가한 호감도 레벨의 총 레벨업 호감도 값으로 갱신한다.

- 캐릭터를 획득한 직후의 초기 상태에서는 `호감도 레벨=1` / `현재 누적 호감도=0`으로 설정된다.

- 호감도 레벨이 n인 캐릭터의 호감도 값을 UI에 출력할 때 이하의 내부 변수 값을 사용한다.

    - `현재 레벨업 호감도` : 다음 호감도 레벨(n+1)의 총 레벨업 호감도 - 현재 호감도 레벨(n)의 총 레벨업 호감도

    - `현재 레벨 누적 호감도` : 캐릭터의 현재 누적 호감도 - 현재 호감도 레벨(n)의 총 레벨업 호감도

### 1.6.1. 호감도 스토리

- 각 캐릭터마다 정해진 호감도 레벨에 도달하면 스토리가 개방된다.

    - 호감도 스토리 개방 정보는 캐릭터 종류(메인, 지원) / 캐릭터 ID / 호감도 레벨로 구성되며, [RapportStory] 테이블에서 관리한다.

    - 각 호감도 스토리는 `개방됨`  (bool) 내부 변수를 가지며, 초기 상태에서는 `개방됨=false`로 설정된다.

- 호감도 레벨 업 처리 시 레벨 업 후의 호감도 레벨 값을 체크한다.

    - 체크한 호감도 레벨이 각 호감도 스토리의 개방에 필요한 호감도 레벨 이상인 경우 해당 호감도 스토리를 `개방됨=true` 상태로 설정한다. (필요 호감도 미만인 경우 `개방됨=false`)

## 2.1. 카메라 설정

- 메인 카메라에 Cinemachine을 적용하여, 플레이어 메인 캐릭터 Transform을 Follow 및 LookAt 대상으로 지정한다.

    - 카메라가 플레이어의 위치 이동을 추적하여 동일한 속도로 이동한다.

## 2.2. 시작 지점

- 각 맵마다 정해진 위치에 시작 지점을 설정한다.

    - 시작 지점에는 플레이어 캐릭터 오브젝트를 출력하는 출력 기준점 Transform 오브젝트가 배치된다.

- 플레이어가 맵에 진입하면 플레이어 캐릭터 오브젝트가 시작 지점에 출력된다.

    - 시작 지점의 출력 기준점 위치와 플레이어 캐릭터의 위치 기준점이 일치하도록 출력한다.

## 2.3. 탈출 지점

- 각 맵에 정해진 개수의 탈출 지점을 설정한다.

    - 탈출 지점에는 플레이어 캐릭터 오브젝트의 탈출 여부를 감지하는 탈출 구역 (Collider) 오브젝트가 배치된다.

        - 탈출 구역 Collider의 Trigger 설정을 활성화한다.

        - 탈출 지점에 데이터 테이블과 연동되는 스크립트를 컴포넌트로 연결하여, 탈출 가능 조건 및 탈출 가능한 플레이어 수를 설정한다.

- 플레이어의 몸통 Collider와 탈출 지점의 탈출 구역 Collider가 접촉하면 OnTriggerEnter 이벤트를 통해 플레이어 탈출 판정을 실행한다.

    - 탈출 판정 실행 시 정해진 채널링 시간 동안 탈출 구역 Collider와 접촉 상태를 유지해야 한다.

    - 채널링 시간 동안 플레이어 상태를 `탈출 중` 상태로 한다.

    - **채널링 없이 즉시 탈출 성공 이벤트를 실행하는 탈출 지점은 채널링 시간을 0으로 입력하여 구현한다**.

    - 채널링 시간 중 탈출 구역 Collider에서 이탈하면 OnTriggerExit 이벤트에 의해 탈출 판정이 취소되며, 해당 플레이어의 상태가 `기본` 으로 변경된다.

- 탈출 구역 Collider에 접촉한 상태를 유지하며 채널링 시간 경과 시 탈출 성공 이벤트를 실행한다.

## 2.4. `[프로토타입 제외]` 시간 제한

- 플레이어는 각 월드 신에 진입한 이후 정해진 시간 동안만 월드에서 플레이를 진행할 수 있다.

    - 월드에서 플레이를 진행할 수 있는 `시간 제한` 값은 [World] 테이블에서 초 단위로 지정한다.

    - 월드에 진입한 플레이어에게 `남은 제한 시간` 내부 변수를 월드의 시간 제한 값만큼 부여한다.

- 플레이어가 월드에서 게임 플레이를 진행하는 동안 시간 경과에 따라 남은 제한 시간 값이 감소한다.

    - 남은 제한 시간 감소 계산은 서버 시간 경과를 따른다.

    - 남은 제한 시간 값은 최소 0까지 감소할 수 있다.

### 2.4.1. `[프로토타입 제외]` 시간 차감 가속

- 월드 맵 내의 정해진 구역에 플레이어가 진입해 있는 경우, 남은 제한 시간이 감소하는 속도가 해당 구역마다 정해진 `시간 배율` 값만큼 가속된다.

    

    $$

    남은 제한 시간 -= 서버 시간 경과×시간 배율

    $$

    

    - 남은 제한 시간이 원래 시간 속도대로 감소하는 구역은 `시간 배율=1` 로 설정한다.

    - 가속 구역 Collider 볼륨에 플레이어 몸통 Collider가 접촉하고 있는 동안 OnTriggerStay 코드를 통해 시간 배율을 적용한다.

## 2.5. 탈출 판정

- 맵 플레이 중 이하의 어느 조건 중 1개 이상이 만족되면 탈출 판정을 실행한다.

    - 플레이어 캐릭터의 보유 체력이 0이 되어 `빈사` 상태에 도달한 상태에서 빈사 시간 경과 → `강제 각성`  상태로 탈출 판정을 실행한다. (탈출 실패)

    - `[프로토타입 제외]` 플레이어 캐릭터의 남은 제한 시간이 0이 됨 → `강제 각성`  상태로 탈출 판정을 실행한다. (탈출 실패)

    - 플레이어가 탈출 지점에 도착 → `탈출 중`  상태로 채널링 시간 경과 후 탈출 성공 이벤트로 탈출 판정을 실행한다. (탈출 성공)

- 탈출 판정 조건은 각 플레이어마다 개별로 계산한다.

### 2.5.1. 탈출 결과 정산

- 탈출 판정 실행 시 탈출 판정을 실행한 시점에서 이하의 데이터를 각각 정산한다.

    - 탈출 성공 or 탈출 실패 값을 저장한다.

    - `[프로토타입 제외]` 보유 체력

    - 신 입장 시점부터 탈출 판정을 실행한 시점까지의 서버 시간 경과 값을 `누적 플레이 시간` 내부 변수로 저장한다.

        - 월드에 지정된 존 입장 시 제한 시간 차감 가속 효과는 적용하지 않는다.

    - `[프로토타입 제외]` 처치한 적 수

    - 이하의 순서에 따라 보유 아이템 정산을 실행한다.

        - 탈출 실패 상태로 탈출 판정이 실행된 경우 각성 보존 슬롯 이외의 인벤토리 리스트에 저장된 아이템은 소멸한다. (탈출 성공 상태로 탈출 판정을 실행한 경우 소멸 처리를 진행하지 않음)

        - 드림 포지드 무장을 분해하여 (분해된 드림 포지드 무장 아이템은 소멸됨) 각 드림 포지드 무장마다 정해진 개수만큼의 무장 파편을 인벤토리 리스트에 등록한다.

        - 보유한 기억 파편 중 플레이어 캐릭터 편성에 대응 캐릭터가 있는 기억 파편에 대하여 캐릭터 호감도 정산을 실행한다. (호감도 정산을 실행한 기억 파편은 소멸됨)

        - 인벤토리 리스트 정산 완료 시 아이템 종류 및 탈출 성공/실패 판정에 따라 이하와 같이 정산된다.

            

            

            | 아이템 종류 | 각성 보존 슬롯 보관 | 탈출 성공 | 탈출 실패 |

            | --- | --- | --- | --- |

            | 기본 무장 |  | 인벤토리에 유지됨 | 인벤토리에 유지됨 |

            | 특화 무장

- 결과 창의 RETRY 버튼을 터치하면 현재 월드 신을 다시 로드하여 신 이동을 실행한다.

# 3. 아이템

## 3.1. 아이템 생성 및 상호작용

- 월드 신이 생성되는 시점에 월드 신마다 지정된 위치에 아이템이 생성된다.

    - 월드 신에 생성된 아이템(이하 `월드 아이템` 에는 아이템 종류와 드롭 개수 값을 갖는다.

- 아이템과 플레이어가 상호작용하면 해당 플레이어의 인벤토리에 상호작용한 아이템을 등록하는 처리를 이하와 같이 진행한다.

    - 인벤토리 리스트에 상호작용한 아이템과 동일한 아이템이 존재하는지 확인한다.

        - 동일한 아이템이 존재하는 경우 인벤토리 리스트에 등록된 아이템의 “중첩 용량 남은 개수” (`중첩 용량 - 현재 중첩 개수`) 값과 상호작용한 월드 아이템의 드롭 개수 값을 비교한다.

            - 중첩 용량 남은 개수 = 0인 경우 ‘획득 불가’ 처리만 출력하고 아이템 등록 처리를 중단한다.

            - 중첩 용량 남은 개수 < 드롭 개수인 경우 중첩 용량 남은 개수까지만 현재 중첩 개수를 증가시키고 (현재 중첩 개수 = 중첩 용량 값) 같은 수치만큼 월드 아이템에서 감소시킨 후 나머지 수량은 월드 아이템의 드롭 개수로 유지한다.

            - 중첩 용량 남은 개수 ≥ 드롭 개수인 경우 상호작용한 아이템의 드롭 개수만큼 현재 중첩 개수가 증가한다.

        - 동일한 아이템이 존재하지 않는 경우 인벤토리 리스트의 남은 슬롯 개수를 체크한다.

            - 남은 슬롯 개수가 0인 경우 ‘획득 불가’ 처리만 출력하고 아이템 등록 처리를 중단한다.

            - 남은 슬롯 개수가 1 이상인 경우 상호작용한 아이템을 남은 슬롯 중 1개에 등록하고, 등록한 아이템의 획득 개수를 현재 중첩 개수에 대입한다.

    - 인벤토리 등록 처리 후 월드 아이템의 드롭 개수가 0이라면 월드 아이템에 소멸 처리를 실행한다.

        - 월드 맵의 아이템 오브젝트를 비활성화하여 아이템 ObjectPool로 되돌린다.

## 3.2. 인벤토리

- 월드에서 상호작용하여 획득한 아이템은 인벤토리에 등록된다.

- 인벤토리는 월드 메인 UI에서 인벤토리 버튼을 터치하여 출력되는 인벤토리 팝업에서 확인할 수 있다.

- 인벤토리 UI에 출력되는 인벤토리 리스트는 가로 X칸 × 세로 Y칸의 그리드 공간으로 설정된다.

    - 슬롯 개수를 인벤토리 리스트 용량 값만큼 출력하며, 가로로 X칸만큼 출력 후 다음 세로줄에 가로로 출력하는 형식으로 배치한다.

    - 인벤토리 리스트 UI의 가로 또는 세로 크기가 인벤토리 팝업 UI의 리스트 공간보다 큰 경우 해당 방향에 드래그 가능한 스크롤을 출력하여 나머지 리스트 공간을 확인할 수 있게 한다.

- TID가 같은 아이템을 2개 이상 중복 획득한 경우 각 아이템마다 정해진 `중첩 용량` 수치까지 보유할 수 있다.

    - TID가 같은 아이템을 중복 획득한 경우 인벤토리 리스트에서 TID별로 1개 슬롯을 사용한다.

    - 인벤토리에 보유한 아이템은 각각 `현재 중첩 개수` 를 내부 변수로 가진다.

    - 인벤토리 리스트의 슬롯 UI에 “현재 중첩 개수 / 중첩 용량” 텍스트를 출력하여 표시한다.

## 3.3. 무장

- 플레이어가 장착하여 적을 공격하는 데에 사용하는 아이템.

### 3.3.1. 오브젝트 구성

- 무장 아이템 오브젝트는 이하의 하위 오브젝트로 구성된다.

    - 손잡이(transform): 플레이어 캐릭터가 무장 장착 시 플레이어 캐릭터의 손 오브젝트와 무장 아이템 오브젝트의 위치 및 방향을 일치시키는 기준점.

    - 총구(transform): 기본 공격 루틴이 출력되는 위치 및 방향 기준점.

    - 공격 이펙트 (particle system): 기본 공격 루틴 실행 시 출력되는 공격 이펙트 오브젝트.

### 3.3.2. 무장 획득

- 월드 맵에 생성된 무장 아이템은 플레이어가 오브젝트 상호작용을 통해 획득할 수 있다.

- 획득한 무장은 인벤토리에 등록된다.

### 3.3.3. 무장 장착

- 상호작용으로 획득한 무장 아이템은 인벤토리에서 장착할 수 있다.

    - 인벤토리에서 무장 아이템 아이콘을 드래그하여 무장 슬롯에 드롭하면 무장 장착 처리를 실행한다.

        - 무장 슬롯에는 아이템 종류가 `category=weapon` (무장)인 아이템을 장착한다.

        - 드래그한 아이템의 종류가 `category≠weapon` (무장 아님)인 경우 무장 장착 처리를 실행하지 않고 종료한다.

        - 드롭한 슬롯에 장착 중인 무장이 없는 경우: 드래그한 무장 아이템을 그대로 드롭한 무장 슬롯에 장착한다.

        - 드롭한 슬롯에 장착 중인 무장이 있는 경우: 드롭한 슬롯에 장착 중인 기존 무장의 장착을 해제한 후, 드롭한 슬롯에 드래그한 무장 아이템을 장착한다.

### 3.3.4. 기본 공격 루틴

- 기본 공격 루틴 발생 시 이하의 순서에 따라 처리를 실행한다.

    - 기본 공격에 필요한 마나 수량만큼 플레이어 보유 마나가 감소한다.

    - 장착 중인 무장에 지정된 공격 이펙트가 출력된다.

    - 장착 중인 무장에 지정된 공격 범위 내에 해당하는 적에게 명중 판정 이벤트를 발생시킨다.

        - 명중 판정 이벤트는 현재 몽막 피해 → 현재 체력 피해 → 사망 처리 → 심상핵 노출 상태 순서로 실행한다.

### 3.3.5. `[프로토타입 제외]` 재장전

- 기본 공격 루틴은 정해진 탄창 용량 수치만큼만 연속으로 실행할 수 있다.

    - `현재 탄창`(int)과 `재장전 중`(bool)을 내부 변수로 지정한다.

        - 예외 처리: 재장전 루틴을 실행하지 않는 무장은 현재 탄창 값을 0 미만인 값으로 지정한다.

    - 기본 공격 루틴을 실행할 때마다 실행된 횟수만큼 현재 탄창 값이 감소한다.

- 현재 탄창이 0이 된 시점에 이하의 순서에 따라 재장전 루틴을 실행한다.

    - `재장전 중=true` 상태가 된다.

    - `재장전 시간`만큼 대기한다.

    - `현재 탄창` 값을 `탄창 용량` 수치만큼으로 초기화한다.

    - `재장전 중=false` 상태가 된다.

## 3.4. `[프로토타입 제외]`방어구

- 플레이어가 장착하여 방어막/방어력 수치를 얻는 아이템.

    - 방어구 아이템을 장착한 플레이어는 방어구에 설정된 방어막 수치 합계만큼의 `최대 방어막` (float) 값을 내부 변수로 가진다.

        - 추가로, 현재 시점의 방어막 수치를 가리키는 `현재 방어막` (float) 및 방어막 재생 효과 발동 여부 판정에 사용되는 `최근 피격 시점` (time)을 내부 변수로 가진다.

        - 현재 방어막 수치가 최대 방어막 수치 미만인 상태에서 마지막 피격 판정 후 `방어막 재생 대기시간` 이상 시간 경과 시, 현재 방어막이 1초마다 `초당 방어막 회복량` 만큼 증가한다. (최대 방어막 값까지)

        - 현재 방어막 수치가 1 이상인 상태에서 플레이어 캐릭터가 적 캐릭터 공격에 피격 시 피격 경직 판정이 발생하지 않는다.

    - 방어구 아이템을 장착한 플레이어는 방어구에 설정된 방어력 수치 합계만큼의 `총 방어력` (float) 값을 내부 변수로 가진다.

        - 총 방어력은 `최대 방어력`  상수 값 이하로 적용한다. (최대 방어력 값은 밸런스 기획에서 설정)

### 3.4.1. `[프로토타입 제외]`정신 과부하 페널티

- 각 방어구 아이템에는 정신 과부하 페널티가 존재한다.

    - 정신 과부하 페널티로는 `마나 회복 속도 감소` 및 `이동 속도 감소` 가 존재한다.

        - 마나 회복 속도 감소 및 이동 속도 감소 페널티는 합연산으로 적용되며, 각각  `마나 회복 감소 최대값` 및 `이동 속도 감소 최대값` 상수 이하로 적용한다. (각각의 상수 값은 밸런스 기획에서 설정)

        - 마나 회복 증가 또는 이동 속도 증가 버프를 적용할 경우 해당 버프 수치만큼의 음수(-) 값으로 입력하여 적용할 수 있다.

## 3.5. 소비 기물

- 플레이어가 월드에서 사용하여 정해진 효과를 발동하는 아이템.

- 각 소비 기물에 지정된 효과를 발동하기 위한 사용 처리는 이하의 순서대로 실행한다.

    - 사용 처리 시작 시 발동 타입(`useType`) 체크를 실행하고, 발동 타입에 따라 발동 지점을 지정한다.

        - self: 플레이어 자신의 위치 기준점을 발동 지점으로 지정한다.

        - circle_zone: 플레이어로부터 `사용 거리`  반경 내의 원형 공간 내 임의의 지점을 터치하여, 터치한 지점을 중심으로 하고 `소비 효과 범위`  반경 내의 원을 발동 지점으로 지정한다.

        - target: 플레이어로부터 `사용 거리`  반경 내의 원형 공간 내에서 단일 대상을 선택하여, 선택한 대상의 위치 기준점을 발동 지점으로 지정한다.

        - raycast: 사용 처리 판정 ray를 발사할 방향을 선택하고, 발사할 방향으로 `사용 거리`만큼 진행한 지점을 발동 지점으로 지정한다.

        - rectangle: 사용 처리가 발동할 직사각형 구역의 세로 거리 방향을 선택하고, `사용 거리 × 소비 효과 범위`  크기의 직사각형 범위를 발동 지점으로 지정한다.

        - 단일 대상에게 적용하는 효과(self, target, raycast)는 소비 효과 범위=0으로 입력한다.

    - 소비 기물마다 정해진 `발동 대기 시간`  동안 소비 기물 효과를 발동하지 않고 대기한다.

        - `발동 대기 시간=0`인 경우 즉시 발동한다.

        - `[프로토타입 제외]` 소비 채널링=true인 소비 기물은 발동 대기 시간 동안 채널링 체크를 실행한다.

            - 발동 대기 시간 동안 적 캐릭터에게 피격 시 소비 기물의 사용 처리가 취소된다: 소비 효과가 적용되지 않고, 소비 기물의 현재 중첩 개수도 감소하지 않음

    - 발동 대기 시간 경과 후 발동 타입(`useType`)에 따라 발동 지점에서 소비 효과를 적용한다.

        - self, circle_zone, target, rectangle: 발동 지점 내에서 `소비 효과 대상` 에 해당하는 대상에게 `소비 효과 분류` 및 `소비 효과 값` 으로 정해진 효과를 적용한다.

        - raycast: 플레이어 위치 기준점에서 발동 지점 방향으로 ray를 발사하여, ray가 hit한 대상 중 `소비 효과 대상` 에 해당하는 가장 가까운 대상에게 `소비 효과 분류` 및 `소비 효과 값` 으로 정해진 효과를 적용한다.

    - 소비 효과 적용 후 사용한 소비 기물의 현재 중첩 개수를 1 감소한다.

        - 소비 기물의 현재 중첩 개수가 0이 된 경우, 소비 기물을 인벤토리에서 제거한다.

### 3.5.1. 퀵슬롯

- 인벤토리 리스트에 등록한 아이템을 퀵슬롯에 장착할 수 있다.

    - 퀵슬롯에는 아이템 종류가 `category=consume` (소비 기물)인 아이템을 장착한다.

- 각 퀵슬롯에는 Input System을 통해 퀵슬롯 사용 키를 등록한다.

- 인벤토리 리스트 UI에서 아이템을 드래그하여 퀵슬롯에 드롭 시 퀵슬롯 장착 처리를 실행한다.

    - 드래그한 아이템의 종류를 체크한다.

        - 아이템 종류가 `category≠consume` (소비 기물 아님)이면 퀵슬롯 장착 처리를 곧바로 종료한다.

        - 아이템 종류가 `category=consume` (소비 기물)이면 이하의 퀵슬롯 장착 성공 처리를 실행한 후 퀵슬롯 장착 처리를 종료한다.

            - 드래그한 아이템의 아이콘을 퀵슬롯에 출력한다.

            - 드래그한 아이템의 현재 중첩 개수 텍스트를 퀵슬롯에 출력한다.

    - 퀵슬롯 장착 처리를 종료한 후 인벤토리 리스트에서 드래그한 아이템은 드래그 전의 인벤토리 슬롯 위치에 유지된다.

- 소비 기물이 장착된 퀵슬롯의 퀵슬롯 사용 키를 터치하면 등록한 소비 기물의 사용 처리를 실행한다.

## 3.6. 기억 파편

- 플레이어 캐릭터의 호감도 상호작용에 사용되는 아이템.

    - [Item] 데이터 테이블에서 `itemCategory=memory`(기억 파편)인 아이템으로 정의된다.

- 기억 파편 아이템의 상세 동작에 참조하는 데이터는 [MemoryPiece] 테이블에서 관리한다.

    - [MemoryPiece] 테이블에는 각 기억 파편의 대응 캐릭터 및 `호감도 정산 값` 데이터를 기록한다.

        - 대응 캐릭터 데이터는 `캐릭터 종류` (메인 / 지원) 및 `캐릭터 ID`  값으로 구성된다.

### 3.6.1. 캐릭터 호감도 정산

- 월드 신에서 획득한 기억 파편 아이템은 탈출 판정 시 캐릭터 호감도 정산에 소비된다.

- 캐릭터 호감도 정산은 월드 신에서 탈출 판정 실행 시 탈출 실패에 따른 아이템 소멸 판정 이후에 실행한다.

    - 인벤토리에 보관된 기억 파편 아이템은 탈출 실패 시 캐릭터 호감도 정산이 실행되지 않고 그대로 소멸한다.

    - 각성 보존 슬롯에 보관된 기억 파편 아이템은 탈출 실패 시 소멸 처리가 실행되지 않으므로 정상적으로 캐릭터 호감도 정산이 실행된다.

- 캐릭터 호감도 정산은 이하의 규칙 순서에 따라 진행한다.

    - 기억 파편 아이템 데이터의 캐릭터 종류 및 캐릭터 ID 값을 통해 대응 캐릭터 1명을 찾는다.

    - 찾은 대응 캐릭터의 총 누적 호감도를 호감도 정산 값만큼 증가시킨다.

        - 월드 신에 편성된 플레이어 캐릭터(메인 및 서브) 중 대응 캐릭터가 존재하지 않는 기억 파편은 호감도 정산을 실행하지 않는다.

    - 대응 캐릭터의 총 누적 호감도 값이 증가 처리 직전 시점의 호감도 값에 설정된 총 레벨업 호감도 값 이상이 된 경우 호감도 레벨 업 처리를 실행한다.

    - 기억 파편 아이템을 인벤토리에서 제거한다.

# 4. 적

## 4.1. 오브젝트 구성

- 적 캐릭터 오브젝트는 이하의 하위 오브젝트로 구성된다.

    - 위치 기준점 (Transform): 적의 위치 및 방향(Y 위, Z 정면) 정보를 계산하는 기준점.

    - 몸통 (Collider): 적과 다른 구성 요소 사이의 접촉 상호작용 발동 여부를 판정하는 기준 영역.

        - 장애물 판정을 위해 Trigger 설정을 비활성화한다.

## 4.2. 적 상태 제어

- 적 캐릭터의 행동 패턴은 이하의 `enemyState` (enum) 상태에 따라 제어한다.

    - idle `대기`

    - detect `추적`

    - attack `공격`

    - hit `피격`

    - dead `사망`

- 적 캐릭터 오브젝트에 플레이어 추적 패턴을 설정한다.

    - 플레이어 추적 패턴은 시야 거리만큼의 반지름과 시야 각도만큼의 사이각을 가지는 부채꼴 영역(이하 `추적 영역`) 내에서 작동한다.

        - 추적 영역은 위치 기준점 정면 방향에서 좌우(각각 -,+ 방향)로 시야 각도 값의 절반만큼 벌린 영역이 된다.

    - 적 캐릭터의 추적 영역 내에 플레이어가 진입하면 적의 추적 상태가 `추적` 으로 변경된다.

        - 플레이어 진입 판정은 매 프레임마다 갱신된다.

        - 플레이어 진입은 플레이어의 위치 기준점이 추적 영역 내에 위치하는지 여부로 판정한다.

            - 추적 영역 내에 플레이어의 위치 기준점 오브젝트가 없으면 `대기` 상태로 돌아간다.

        - `강제 각성` 상태나 `탈출 중` 상태인 플레이어는 진입 판정을 실행하지 않는다.

        - `추적` 상태인 적 캐릭터는 추적 영역 내의 플레이어 중 거리가 가장 가까운 캐릭터를 향해 이동한다.

            - 적의 위치 기준점 정면 방향을 플레이어 위치 방향으로 Rotate시킨다. (보간 적용)

    - 추적 영역 내에 적 캐릭터와의 거리 값이 공격 사거리 이하인 플레이어 캐릭터가 있으면 적의 추적 상태가 `공격` 으로 변경된다.

        - 공격 상태인 적은 위치 기준점 사이의 거리가 가장 가까운 플레이어 1명에게 기본 공격 루틴을 실행한다. (각 적에게 지정된 기본 공격 스킬을 발동)

            - 공격 애니메이션을 재생하고, 피해 판정 이벤트가 입력된 시점에 공격 대상 플레이어에게 체력 감소 처리를 발생시킨다.

                - 공격 시작 시점부터 피해 판정 이벤트가 입력된 시점까지의 시간 간격을 공격 쿨타임 데이터로 관리한다.

        - 공격 루틴 실행 후 공격 간격 시간 동안 대기한다.

            - 대기 중 추적 영역 내의 플레이어 캐릭터를 검색하여 추적 상태를 갱신한다.

- 플레이어가 적 캐릭터를 공격 시 피격 판정이 발생한다.

    - 피해 계산 후 남은 보유 체력 수량을 체크한다.

        - 피격된 적 캐릭터의 보유 체력이 0 이하가 된 경우 적 사망 처리를 실행한다.

        - 피격된 적 캐릭터의 보유 체력이 1 이상인 경우 슈퍼아머 상태 여부를 체크한다. (슈퍼아머 상태는 `[프로토타입 제외]` )

            - 슈퍼아머 상태인 경우 적 캐릭터 상태를 피격 판정 시점의 상태로 유지한다.

            - 슈퍼아머 상태가 아닌 경우 적 캐릭터 상태를 `enemyState=hit` (피격)으로 변경한다.

                - 피격 상태로 변경 시 플레이어 추적 패턴을 해제하고 피격 애니메이션을 재생한다(경직 상태)

                - 피격 애니메이션 재생 길이만큼 시간 경과 후 적 캐릭터 상태를 `enemyState=idle` (기본)으로 변경하고 플레이어 추적 패턴을 다시 실행한다.

                    - 다음 프레임에 플레이어와 적 사이의 거리에 따라 enemyState가 detect 또는 attack으로 갱신된다.

## 4.3. `[프로토타입 제외]` 몽막 / 심상핵

- 적 캐릭터는 몽막 게이지 및 `심상핵 노출` (bool) 상태를 내부 변수로 가진다.

    - 월드에 스폰된 적은 ‘현재 몽막’ (float) 값을 내부 변수로 가지며, 월드에 활성화된 시점에 몽막 게이지 값만큼의 현재 몽막을 보유한 상태로 스폰된다.

    - 심상핵 노출 값은 (현재 몽막 값이 0 이하인가)를 기록하며, 초기 상태에서는 false로 설정된다.

- 플레이어의 공격(무장 기본 공격 및 스킬)에는 각각 정해진 `몽막 공격력` 수치를 가진다.

    - 플레이어의 공격이 적에게 히트 시 몽막 공격력만큼 대상 적의 현재 몽막 값이 감소한다.

    - 현재 몽막 피해 계산은 보유 체력 피해 계산보다 먼저 적용되며, 별개의 메소드를 통해 동작한다.

- 플레이어의 기본 공격 및 스킬에 피격되어 적 캐릭터의 몽막 게이지가 0 이하가 되면 `심상핵 노출=true` 상태가 된다.

    - 심상핵 노출 상태 판정은 현재 몽막 피해 계산과 별개의 메소드를 통해 동작하며, 보유 체력 피해 계산보다 나중에 적용한다.

- 심상핵 노출 상태인 적을 플레이어가 기본 공격 및 스킬로 공격 시, 적의 보유 체력이 감소하는 피해량이 적 종류에 따라 정해진 심상핵 치명타 배율만큼 증가된다.

    

    $기본 피해량 × (1 + 심상핵 치명타 배율)$

    

- `심상핵 노출=true` 상태로 몽막 재생 시간만큼 시간 경과 시 이하의 몽막 재생 처리를 실행한다.

    - 현재 몽막 값을 몽막 게이지 값으로 초기화한다.

    - `심상핵 노출=false` 상태가 된다.

# 5. 전투

## 5.1. 피해 계산

- 플레이어 및 적 캐릭터는 보유 체력(float)을 내부 변수로 가진다.

    - 보유 체력은 각 캐릭터가 월드에 등장한 시점에 최대 체력 값만큼의 초기값을 부여받는다.

- 플레이어의 공격으로 적에게 명중 판정 발생 시 적의 보유 체력이 감소한다.

- 적이 공격 루틴을 실행하여 플레이어의 보유 체력을 감소시킨다.

- 공격받은 대상의 보유 체력이 감소하는 수량은 이하의 수식을 사용하여 계산한다.

    

    $$

    체력감소_B=공격력_A×공격 배율_A×(1-방어력_B)

    $$

    

    - A:공격한 대상, B: 공격받은 대상.

    - 기본 공격은 [공격 배율]을 100%로 입력하여 사용한다.

- `프로토타입 제외` 현재 방어막이 1 이상인 플레이어에게 보유 체력 감소 판정이 발생한 경우, 현재 방어막 값이 보유 체력 값보다 우선하여 감소한다.

    - 체력 감소량이 보유 방어막 값을 초과하는 경우, 그 넘은 분량만큼 보유 체력 값을 감소시킨다.

## 5.2. 체력 소진 시 처리

- 공격받은 대상의 보유 체력이 0 이하가 되면 대상의 종류에 따라 사망 처리를 실행한다.

### 5.2.1. 플레이어 - 빈사 → 강제 각성

- 플레이어의 livingState 상태를 down(`빈사`)으로 변경한다.

- 빈사 상태인 플레이어는 다른 플레이어가 오브젝트 상호작용 가능한 상태가 된다.

- 월드 내에서 기본 또는 탈출 중 상태인 플레이어 수를 체크하여 `구조 가능`(int) 변수로 저장한다.

    - 구조 가능 체크는 월드 내 플레이어의 수 및 livingState 상태가 변경되는 시점마다 실행한다.

        - 플레이어가 월드 신에 진입한 시점

        - 월드 내 임의의 플레이어가 빈사 상태가 된 시점

        - 월드 내 임의의 플레이어가 탈출 성공 이벤트를 실행하여 월드 신에서 이탈한 시점

    - `구조 가능 = 0`이 된 시점에 즉시 모든 빈사 상태 플레이어에게 사망 처리를 실행한다.

        - **월드 내 플레이어가 1명인 상황에서 그 1명이 빈사 상태가 되면 다른 구조 가능한 플레이어가 없으므로 즉시 사망 처리가 실행된다.**

- 빈사 상태로 변경된 시점부터 정해진 `빈사 시간` 값에 해당하는 시간 경과 시 해당 빈사 상태 플레이어에게 사망 처리를 실행한다.

- 사망 처리는 이하의 순서대로 실행된다.

    - livingState를 gameover(`강제 각성`)으로 변경한다.

    - 탈출 실패 이벤트를 전달하여 탈출 판정을 실행한다.

    - 탈출 판정 종료 시 해당 플레이어의 오브젝트를 월드에서 제거한다.

#### 5.2.1.1. `[프로토타입 제외]`빈사 소생

- 월드에 빈사 상태인 플레이어가 있을 경우, 구조 가능한 다른 플레이어가 빈사 상태인 플레이어를 구조할 수 있다.

    - 구조 가능한 플레이어가 빈사 상태인 플레이어에게 접근 시 오브젝트 상호작용 규칙에 따라 상호작용 시작 이벤트를 실행하여 상호작용 버튼을 출력한다.

    - 상호작용 처리 실행 시 `소생 시간`  동안 소생 채널링 체크를 실행한다.

        - 소생 채널링 체크 중에도 빈사 시간 경과가 계속해서 진행된다.

        - 소생 채널링 체크 중 상호작용 키 입력 홀드를 유지한 상태로 소생 시간 경과 시 소생 완료 처리가 발동한다.

        - 소생 채널링 체크를 실행하는 플레이어가 빈사 상태 플레이어의 상호작용 구역 Collider에서 이탈 시 소생 채널링 체크가 취소된다.

        - 소생 채널링 체크 중 적 캐릭터에게 피격 시 소생 채널링 체크가 취소된다.

    - 소생 완료 처리 발동 시 빈사 상태 플레이어에게 이하의 소생 성공 처리를 실행한다.

        - 보유 체력을 최대 체력 × `소생 시 체력 비율`  값으로 설정한다.

        - livingState를 idle(`기본`)으로 변경한다.

### 5.2.2. 적 사망 처리

- 적 캐릭터 상태를 `enemyState=dead` (사망)으로 변경한다.

- 플레이어 추적 패턴을 해제하고 사망 애니메이션을 재생한다.

- 사망 상태로 변경된 시점에 전리품 스폰 처리를 실행한다.

    - 전리품 목록에 기재된 각 아이템을 적 처치 위치에 생성한다.

- 사망 애니메이션 재생 길이만큼 시간 경과 후 적 캐릭터 오브젝트를 비활성화하여 적 ObjectPool에 전달한다.

## 7.6. Skill

- 메인 캐릭터/지원 캐릭터 호출/적 캐릭터가 사용하는 스킬 데이터를 통합 관리하는 테이블.

    - 1개 스킬에 2종류 이상의 효과를 부여하는 경우 effectType / effectDelay / effectValue를 효과 개수만큼 사용하며, 각 효과는 _XX 부분에 숫자 번호를 입력하여 구분한다. (00부터 시작)

  • main: 플레이어 메인 캐릭터

  • strike: 플레이어 지원 캐릭터

  • enemy: 적 캐릭터 |

| 2 | skillType | enum | 스킬 종류 | 각 스킬의 스킬 종류 타입

  • base: 기본 공격

  • passive: 패시브 스킬

  • manual: 수동 액티브 스킬

  • auto: 자동 액티브 스킬 |

| 6 | effectType_XX | enum | 스킬 효과 종류 | 각 스킬의 효과 종류 타입

  • none: 사용되지 않음

  • damage: 보유 체력 피해

  • healHP: 보유 체력 회복

  • leap: 도약,돌진 |

| 7 | effectDelay_XX | float | 스킬 딜레이 | 각 스킬의 루틴 시작 후 해당 효과가 발생할 때까지의 쿨타임

  • 즉시 발동하는 경우 0으로 입력 |

  • `effectType=heal`: 보유 체력 회복량(float 변환)

## 7.12. Consume

- 월드 내에서 소모하는 서바이벌 소비 기물 아이템의 데이터.

    - 1개 소비 기물에 2종류 이상의 효과를 부여하는 경우 effectType / effectValue를 효과 개수만큼 사용하며, 각 효과는 _XX 부분에 숫자 번호를 입력하여 구분한다. (00부터 시작)

| No. | Index | 자료형 | 데이터명 | 설명 |

| --- | --- | --- | --- | --- |

| 0 | TID | int | 고유 ID | 각 소비 기물 효과의 고유 ID |

| 1 | useType | enum | 발동 타입 | 각 소비 기물의 사용 처리 시작 시 발동 종류 타입

  • **self: 사용한 플레이어 자신을 대상으로 발동**

  • target: 사용 처리가 발동할 단일 대상을 선택

  • circle_zone: 사용 처리가 발동할 원형 구역의 중심 지점을 선택

  • raycast: 사용 처리 판정 ray를 발사할 방향을 선택

  • rectangle: 사용 처리가 발동할 직사각형 구역의 세로 거리 방향을 선택 |

| 2 | useRange | float | 사용 거리 | 사용 처리 시작 시 발동 지점/대상을 선택할 수 있는 최대 거리

  **• `useType=self` 인 경우 0으로 입력** |

| 3 | useDelay | float | 발동 대기 시간 | 발동 타입 처리 후 소비 효과가 적용되는 시점까지의 딜레이 시간 값

  **• 대기 없이 즉시 발동하는 경우 0으로 입력** |

| 4 | isChanneling

`[프로토타입 제외]` | bool | 소비 채널링 | 발동 대기 시간 중 채널링 적용 여부 값

  • true인 경우 발동 대기 중 피격 시 사용이 취소됨 |

| 5 | effectRange | float | 소비 효과 범위 | 발동 대기 시간 후 소비 효과가 적용되는 범위

  **• `useType=self** || target || raycast` **: 0으로 입력**

  • `useType=circle_zone` : 사용 처리가 발동할 원형 구역의 반지름을 입력

  • `useType=rectange` : 사용 처리가 발동할 직사각형 구역의 가로 폭을 입력 |

| 6 | effectTarget_XX | enum | 소비 효과 종류 | 각 소비 기물 효과를 적용할 대상 타입

  • none: 적용할 효과 없음

  • **self: 사용한 플레이어 자신**

  • enemy: 적 캐릭터 |

| 7 | effectType_XX | enum | 소비 효과 분류 | 각 소비 기물 효과의 종류 타입

  • none: 적용할 효과 없음

  • **mana_recover_inst : 마나 즉시 회복** |

| 8 | effectValue_XX | string | 소비 효과 값 | 각 소비 기물 효과의 적용 수치

  • 0: 적용할 효과 없음

  • **`effectType==mana_recover_inst` (마나 즉시 회복): 마나 회복량 (float 변환)** |
